## 1. 源码优化（2026-09-24）

> 触发语（作者原话）：「**源码优化一下 需要健壮 能复用就复用 找找有没有专门这插件的优化语言的思路**」。
> 纪律：**先量再改** —— 没有为了 DRY 而 DRY（见 §1.4「故意没做的三处」）。

### 1.1 体检数据（改之前先量的）

| 检查项 | 结果 | 判断 |
|---|---|---|
| 重复行（去空白 ≥26 字符、出现 ≥3 次） | 18 组 | 多数是**工具契约要求**的样板（`additionalProperties:false` ×9 等）—— 不是坏味道 |
| 裸 `JSON.parse`（前 240 字符没有 `try`） | **0** | ✅ 已经健壮，不用动 |
| 未被引用的导出 | `findLevelAll` / `findClientProcess` 疑似死代码；`fieldsAll` **有人用**（`tools/gil-field.mjs`） | 记着，先不删（小、公开形状） |
| **写盘的实现** | ❌ **同一个动作三种写法** | 见 §1.2 ③ |
| lint / 类型检查 | ❌ 都没有 | 见 §1.3 ① |

### 1.2 三处真问题（都有取证）

**① ★★ `miliastra_sim` 的 schema 里有**两个 `all`** —— 后者静默覆盖前者**

```
index.js:1521  no-dupe-keys  Duplicate key 'all'
```

`parameters` 里 `all` 出现两次：一个给 `op=keys`（拿全量键名）、一个给 `op=cases action=remove`（删整组）。
JS 对象字面量**后者胜** ⇒ AI 读到的 schema 里 `all` 只被描述成"删整组"，**「`op=keys all:true`」那条从未到达 AI**。
功能"能用"、637 项测试全绿 —— **只有 `no-dupe-keys` 看得见它**。修法：合成一个 `all`，两种用法写在同一个说明里，
并在源码里留注释说明**为什么不能写成两个键**。

**② ★ `lib/client.js` 的 `var s29` 重复声明（维护地雷）**

692 行它是 `uiInfo` 的 state，707 行**又声明一次**当 `panelTab` 用 —— `var` 复用同一个绑定，
当前靠"先读后写"侥幸正确；只要有人调换两段顺序，`uiInfo` 就会**静默变成** panelTab。已改名 `panelTabState` + 留注释。

**③ ★★ 写盘三种实现并存（"能复用就复用"最该修的地方）**

| 位置 | 原来 | 风险 |
|---|---|---|
| `codefile.mjs` | 硬化版（同目录 tmp + **`fsync`** + rename + 失败清理 + 不跨卷） | ✅ 唯一正确的那份 |
| `sim.mjs` 的 JSON（清单 / 配方） | **手搓** tmp+rename | 没 fsync；失败会把 `.tmp<pid>` **漏在盘上** |
| `sim.mjs` 截图 / 导出 | **裸 `fs.writeFileSync`** | 被杀进程可能留下**半截 PNG / 半截 .gia** |

### 1.3 落地了什么

**① 语言层绊线 `tools/lint.mjs`（`npm run lint`，已接进 `npm test`）**

- 规则**故意窄**：只开 20 条"命中即真问题"的硬规则 —— `no-undef`（变量名拼错）/ `no-dupe-keys`（键静默覆盖）/
  `no-unreachable` / `use-isnan` / `valid-typeof` / `no-new-func` / `no-redeclare` / `no-self-assign` / `no-cond-assign` …
  **风格类一条不开**：绊线必须**长期是绿的**，一旦允许几十条风格警告，人（和 AI）就会开始无视它。
- **配置写在代码里**（不落地 `eslint.config.mjs`）：一份真身、少一个会和代码走散的文件；
  顺带避开"配置文件在 A 目录、被扫文件在 B 目录"时 ESLint **直接拒扫**的坑（实测踩过）。
- `eslint` 是 **devDependency**：不进用户运行时。
- 两处**故意的例外**用 `eslint-disable-next-line no-new-func` + 理由标注（`tools/dump-panel-text.mjs` /
  `tools/watch-playtest.mjs`：把 `client.js` 塞进假 `window`/`document` 里**无头渲染面板**，不是 eval 外部输入）。

**② `lib/fsx.mjs`：写盘只有一个实现**

- `atomicWriteFile`（同目录 tmp → `fsync` → `rename` → 失败清 tmp；字符串/`Buffer` 都接）从 `codefile.mjs`
  **搬来这里**，`codefile` 转发（`export { atomicWriteFile }`）—— 老 import 不断，内部照旧用同一个名字。
- 新增 `atomicWriteJson` / `prettyJson`（缩进 2 + 结尾换行，便于人看 diff）。
- `sim.mjs` 四处写盘全部改走共享实现 ⇒ 现在 `sim.mjs` 里 **`fs.writeFileSync` 0 处、`fs.renameSync` 0 处**。

**③ 两处真 bug 修掉**（§1.2 ①②）。

### 1.4 故意**没做**的三处（诚实记录，别当成漏了）

| 看着像重复 | 为什么不动 |
|---|---|
| 4 处 `String(n).padStart(2,'0')` | 其实是**四种不同格式**（`shot` 是 `YYYYMMDD-HHMMSS`，`playtest`/`gia` 只到 `HH:MM:SS`）—— 强合并是过度抽象 |
| 4 个"认字符串的 Lua 扫描器"（`sim` / `lualint` / `leveldata`×2） | 长得像，但一个要**剥掉注释后的文本**、另一个要**原位置（行号）** —— 不是安全替换，宁可放过 |
| index.js 里 **9 份工具样板** | 那是工具契约**要求**的形状；包一层 helper 只增加间接层。它真正危险的那一类（键静默覆盖）现在由 ESLint 兜住 |

### 1.5 靠什么守住（回退 → 绊线对照表）

| 会怎样退化 | 谁在盯 |
|---|---|
| schema 里再出现重复键 / 变量拼错 / 不可达代码 | `tools/lint.mjs`（`npm test` 第一步） |
| 谁把 lint 规则删空、缩小范围 | `tests/smoke.mjs`：断言必须含 `no-dupe-keys` / `no-undef` / `no-unreachable`，且覆盖 `index.js` + `lib/` |
| 谁在 `sim.mjs` 里再写裸 `writeFileSync` / 手搓 `rename` | `tests/sim-test.mjs`：源码绊线（含"必须 import 共享实现"） |
| 原子写退化成"能写进去就行" | `tests/deploy-test.mjs`：不留 `.tmp`、字符串入参、**无 BOM**、失败时**抛错 + 清 tmp + 旧文件完好** |
| 改了工具却忘了重生成 README 工具块 | `tests/readme-test.mjs`：逐字比对（跑 `node tools/gen-readme-tools.mjs --write`） |
| 试玩页布局再被压扁（历史三次） | `tests/sim-play-test.mjs`：四个格子**显式 `grid-row`**、报错条 `max-height:40%`、画布尺寸与版本戳 |
| AI 侧契约退化（典型调用 / level≠stage / summaryOnly / 提示段覆盖 / 请求形状） | `tests/smoke.mjs` 的四条不变量 + 「AI 自己玩」口径 + `op=keys` 的 `press` 形状 |

3. **P3 — D2（跨版本画面对比）**：取决于你要不要"改完代码看画面变了什么"这条链。

## 3. 维护纪律

- **想法池的"真身"仍是 `README.md` 的「想法池」表**（对外、一行即可加、可被反驳）。本文是**汇总视图**：
  新增想法**先加 README 那一行**，再来这里归位；两边冲突以 README 为准。
- **池 C（欠证据）不进 README**：它不是"想法"，写进想法池会让人以为"要做个功能"。
- **这份文档不要写"感觉"**：每条都写清**现状 + 成本 + 谁在盯**；没有取证的判断就标 `推断`。
- **源码优化的记录只增不删**：§1.4「故意没做的三处」要留着 —— 否则下一个人会重新"顺手合并"一遍，
  把当时判断过的取舍再推翻一次。
