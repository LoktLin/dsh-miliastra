## 0. 先说清楚：它在流程里的位置 = **预测试**

> 这一节是「模拟器到底是什么」的一句话答案 —— 2026-09-24 由作者提问补上（「按我理解是预测试模式，是我想的这样吗」）。

```
改代码 → ① 模拟器预测试（游戏外，同一套 Lua + 同一套控件语义）
       → ② 真机试玩（人点按钮；这一步没有自动化通道，也不做）
       → ③ 真机取证（日志 / 截图 / 试玩探针）
```

**能拦下的**（可自动判定）：脚本跑没跑 · 控件建没建 / 建了几个 · 变量与信号对不对 · 布局歪不歪 · 动画动不动。
**拦不下的**（只能真机验）：官方素材 · 真机渲染 · 联机 · 性能 · 手感。所以纪律是那句 —— **模拟器通过 ≠ 真机通过**。

### 三档，共用同一份工程与同一个会话（只理解成"预测试"会漏掉③）

| 档 | 用什么 | 时间怎么走 | 给谁 |
|---|---|---|---|
| **① 静态预览** | `op=state` / `op=controls` / `op=shot` | 不跑 | 看工程长什么样 |
| **② 交互试玩** | `op=play`、面板「模拟器」页、浏览器页 `GET /miliastra/play` | **真在走**（引擎 30FPS 时钟），人可点可拖可按键 | 人玩、AI 观察（`get` / 日志 / `history`） |
| **③ 确定性判定** | `op=verify` / `cases[]` / `fromHistory` / `op=frames` | **冻结时钟**，按时间点精确推进 | AI 自己判（可复现） |

② 与 ③ 是最容易混的：**②是"活的一局"，③是"可复现的重放"**。`verify` 会**开一个全新会话**再按 `t` 重放，
所以同一调用两次结果一样 —— 这也是为什么 `fromHistory` 之后「人那局就结束了」（它把活的一局**转成**了确定性用例）。

### 三条边界（别把它当官方模拟器）

1. **不是官方的，也不是真机**：服务端只覆盖变量与信号（**不含**官方完整节点图）；图片只代理 `100001–100006`，其他显示缺失框；1–8 人是**本地多客户端模拟**，不含真实联机。
2. **不替代人点试玩**：②那档的点/拖/按键是**注入到引擎里**的，不是在替你操作真机（不读内存、不连游戏端口、不冒充编辑器）。
3. **两个方向的 GIA 交换都还是 `pending`**：我们导出的 `.gia` 能否被官方编辑器接受（未验证）；**官方编辑器导出的** `.gia` / Authoring JSON 能否被 `op=import` 吃进来（也未验证）。
   已验证的只有引擎侧往返（自己导出的导回来，控件数一致）。
   ⚠️ 所以「**能不能拿我真机的工程进来预测试**」这件事，目前还差最后这一环节 —— 而它只能人来试（见 §6）。

### ★ 第四条边界：Z 序（2026-09-26 **先实测再写**）

**结论：模拟器真的按 sibling 顺序画**（不是"图片与文字分两遍画"），三条可复现的读数：

| 事实 | 依据 |
|---|---|
| 工程树内部列表是**「前→后」**：**列表第一个 = 最上层** | `engine/studio/test/sibling-order.test.mjs`（`unchanged editor list stays first-on-top`） |
| Lua 的 sibling 序号是**反的**：`SetAsFirstSibling()` / `SetSiblingIndex(0)` = **沉到最底**；`SetAsLastSibling()` / 最大序号 = **提到最上** | 同上（`Lua First lowers and Last raises`）；本轮实测：`SetAsLastSibling()` 后 `GetSiblingIndex()=11`，图确实压住了原在上面的默认按钮 |
| 脚本 `InstantiateClientUIControl` 建的控件**后建的在上** | 0c1fa56 那次真机口径修正 + 本轮回归（先建图、后建文本 ⇒ 采样中心是**文本**） |
| ⚠️ **`op=patch add` 是追加到列表末尾 ⇒ 新控件落在最底层**（与"脚本后建的在上"方向**相反**） | 本轮实测：先 add 文本、再 add 图片，采样点仍是**文本**（= 后加的图片更靠下） |

**没覆盖的（明写，不含糊）**：跨父级只按**父级**顺序整体叠（子控件不会"穿过"父级层序）；
官方素材 / 界面动效**自身内部**的层序；真机渲染管线决定的那部分。
⇒ 「覆盖层压没压住」**仍然建议真机看一眼**，但至少现在你能在模拟器里**先排一遍**：
用 patch 手工搭的时候，要么按倒序 add，要么脚本里 `SetAsLastSibling()` 显式提层。

回归：`tests/feedback4-test.mjs` 的 P2-3 三条（patch add 沉底 / Lua SetAsLastSibling 提层 / instantiate 后建在上）。

## 4. 画面怎么来的（为什么不需要开游戏）

> ⚠️ **2026-09-25 起面板里不再有"画面"这张卡**（作者原话：「画面和截取画面功能很鸡肋不要了 GUI 部分直接删除」）——
> 人要看的画面在**右列那个试玩页 iframe** 里（`GET /miliastra/play`，可点「新窗口 ↗」放大）。
> **工具侧一个字没动**：下面这套 `op=shot`（含连帧的 `reuse:true`）与 `op=frames` 照旧给 AI 用。

`miliastra_sim op=shot`：
- `target=ui` → `renderEditorPng(工程快照)`：编辑器视图（容器/控件框 + 选中态）
- `target=play` → `renderScenePng(试玩场景树)`：**当前试玩帧**

两者都在 **Host 进程内用原生 canvas（`@napi-rs/canvas`）画成 PNG**，然后落进插件数据目录的 `shots/`（命名 `sim-ui-*` / `sim-play-*`，与真机截图同一套命名与清理纪律），面板直接用既有的 `/miliastra/shot?name=…` 显示。
所以：**不需要开游戏、也不要求窗口在前台** —— 这是它与 `miliastra_shot`（抓真窗口）最大的区别。

**连帧用 `reuse:true`**：写**固定名** `sim-play-live.png` / `sim-ui-live.png`（覆盖），URL 带 `&t=<时间戳>` 绕开 `/shot` 路由的 immutable 缓存。
为什么必须这样做：连帧是 5fps，**一小时就是 18 000 张图** —— 每帧新建文件等于把用户的 `shots/` 刷爆。留证据要一张一张存时不要传 `reuse`。

## 4.5 面板上怎么玩（2026-09-24 补齐）

引擎在 Worker 里**本来就以 30 FPS 固定步长自走**（`host/worker.js` 的 `setInterval(33ms)`、`FIXED_DT=1/30`、最多 5 步追帧）。面板只负责**取帧 + 送输入**：

| 动作 | 做什么 | 注意 |
|---|---|---|
| 开始试玩 | `play start`（**面板/页面不带参数** = PC 16:9 / 1 人；AI 可带 `canvasId` 与 `playerCount=1–8`） | 面板与试玩页上的"切换"已按作者要求去掉（见下） |
| ~~连帧：开~~ | **面板里已删**（2026-09-25，它只服务于画面）。要连帧出图给 AI：`miliastra_sim op=shot reuse:true` | 面板不再取图；**工具侧照旧** |
| ~~点画布任意位置~~ | **面板里已删**（面板不再显示画面）。要注入点击：`miliastra_sim op=play action=pointer`，或直接在右列试玩页里点 | `stagePointFromEvent`（左下原点换算）**继续保留并有独立回归** —— 将来谁把"人可点的舞台"加回来，判据必须是同一份 |
| 按键 | 按钮来自 **`op=keys`**（从你脚本源码扫键名，**两路**：`KeyEventType.X` 与裸字符串 `bindHold("KeyboardMoveRightKeyDown",…)`；`found[].via` 标来源），另有输入框可填任意键名 | 脚本里没写 `KeyEventType` 就用引擎的官方键名预设；**扫不出时用 `presets` 试发**，别猜 |
| 单步 | 先 `pause` 再 `step`（跑着的时候那个 30FPS 时钟自己也走） | 单帧确定性调试用 |

> ★ **画布 / 人数 / 视角是固定的**（2026-09-24 作者要求：「我希望固定这样 把切换的功能去掉吧」）：
> 固定 **PC 16:9 / 1 人 / P1**，面板与试玩页上的三个下拉**整块删掉**。两条理由——
> ① 引擎的 `device` 会**重建整个运行时**：画布一变，16:9 的舞台尺寸和 AI 记下的操作坐标都要重算；
> ② 试玩页原来那份**手写**的设备清单里有引擎不存在的预设（`pc-4-3` / `phone-16-9` / `phone-4-3`，
>    引擎只有 `pc-16-9` / `pc-21-9` / `mobile-16-9` / `mobile-19.5-9` / `mobile-4-3`）⇒ 选中就报
>    `unknown canvas preset`（作者截图里那条红条）。
> **能力没丢**：AI 仍可用 `miliastra_sim {"op":"play","action":"device","args":{"canvasId":"mobile-16-9"}}`、
> `action=view`、`playerCount` 去改 —— 只是人在这两个界面上不再有会打歪画布尺寸的开关。
>
> 另有一条**旧陷阱（保留备查）**：`device` 重建运行时，若不同时带上 `playerCount`，人数会**悄悄掉回 1**，
> 随后 `view 2` 报 `playerIndex must be an integer 1-1`。Host 侧已在 `startOpts` 里兜底沿用人数。

能玩的边界（别夸大）：**点按钮 / 看状态变化 / 单步调试** 都行；**需要连续操作的动作类玩法不行**（5fps + 每次点击一次网络往返）。

> 唯一有用的「刷新引擎状态」搬到了试玩页工具条叫「刷新状态」（**错误提示那行保留**）。

- **tab 就是 1:2**（`grid-template-columns:minmax(300px,1fr) 2fr`）：右边那 2 份是**试玩页 iframe**（`GET /miliastra/play`）。
  不把 pixi 塞进面板的理由：WebGL 与自己的 CSP 处理，独立页最稳；它**就是面板里唯一的画面** ——
  左列原来那张"画面"卡（未取图占位 / PNG 缩略图 / 编辑器画面 / 刷新画面 / 连帧）2026-09-25 按作者要求整块删除，
  面板从此不再调 `op=shot`（也就不会再往 `shots/` 写图）。
- **人**：直接在 iframe 里点 / 按键（引擎把这一局记成 history）。
  **AI**：用 `miliastra_sim op=play`（`key`/`pointer`/`step`）驱动**同一个会话** —— 页面每 33ms 轮询场景（`sceneRev` 增量），
  所以 AI 那边一动，这里画面跟着变；反过来，人玩完那一局，AI 用 `op=verify fromHistory:true` 直接变成回归用例。
- **滚动模型**：`-simbody` **不滚**，**左列自己滚**、右列不动 ——
  否则左列一长，滚下去 iframe 就出了视野（作者实测反馈「右侧啥都没」就是这么来的）。

  现在子项一律 `flex:0 0 auto` + `min-height:auto`，滚动交给容器自己。
- **左列宽度下限 300px**（`minmax(300px,1fr)`）：880px 浮层的 1/3 只有 285px，塞不下这些按钮。
- ⚠️ **重启 `dsh web` 之后工程会回到「出厂默认」**（Host 是启动快照）：`op=state` 的 `factoryDefault:true` 会如实说，
  面板顶部会出现一条粉色提示 + **「一键重搭上次：《双相》」**（用成功 bind 时记下的配方 `last-bind.json`）。
  **不自动重搭** —— 那会在人没要求的时候改工程。
- ⚠️ **窄屏兜底：断点是 760px，不是 1000px** —— 浮层面板正好 **880px** 宽，写 1000px 会让浮层**永远命中**媒体查询：

  塌成一列时 iframe 拿 `min-height:min(420px,55vh)`。
- **画布固定 16:9**：`#stage{aspect-ratio:1600/900}` + `#cv{width:100%;height:100%}` —— 比例由 **CSS 声明**，
  JS 只挑宽度（`min(可用宽, 可用高×16/9)`），并把数字印在 footer：`画布 523×294（16:9 固定；可放 543×332）`。
  试玩页自己还有 `@media (max-width:820px)`（嵌在 2/3 列里 ≈ 570px 时收一档、标题换短的，否则工具栏折两行把舞台挤没）。
- iframe 能嵌的前提：**`/miliastra/play` 不要求鉴权**（实测 `curl` 直取 `200`；`/` 才是 401），也没有 `X-Frame-Options` / `frame-ancestors` 拦。

## 4.6 AI 怎么自测逻辑（`op=verify`）★

**一次调用 = 操作 + 断言 + 判定**：

```json
{"op":"verify",
 "steps":[{"key":"KeyboardCraftspersonKey3Down"}],
 "expect":[{"kind":"log","contains":"GOT_KEY_3"}]}
```

→ `{passed:true, failedAt:null, results:[{kind:"log",ok:true,...}], case:{events,asserts}, snapshot:{logs,...}}`

**为什么这么设计**（而不是让 AI 用引擎原生的三跳）：引擎原生是「先交互跑一遍 → `history` → `saveCase` → `runCase`」——对 AI 是三次来回、还要自己算时序。`op=verify` 由 Host 组好用例直接走 `runCase`：它会**开一个全新会话**按 `t` 重放事件、按 `at` 判定断言 ⇒ **每次结果一致**（可重复回归）。
⚠️ `runCase` 需要**活着的 worker**，所以 Host 会先 `start` 一次把**当前**工程送进去（刚 `patch` 的脚本才生效）；重放**不支持 `device` 事件**。

**steps 写法**（事件种类来自引擎 `autotest/runner.js` 的 `applyEvent`）：

| 步骤 | 含义 |
|---|---|
| `{at, after?, key:"KeyboardCraftspersonKey3Down"}` | 注入按键（键名用 `op=keys` 拿） |
| `{click:{x,y}}` | 注入点击（**左下原点**；面板点画布走的也是这条） |
| `{clickName:"预设按钮"}` | 按控件名直接触发点击 |
| **`{drag:{from:[x,y],to:[x,y],steps?,gap?}}`** | **拖拽/滑动**：自动展开成 `down → move… → up`（默认 6 段、每段 0.05 秒）—— 引擎的 `CursorBeginDrag`/`CursorDrag`/`CursorEndDrag` 都在 move 里发，不展开就测不到 |
| `{pointer:{type,x,y}}` | 裸指针事件（`down`/`move`/`up`/`click`），要手排细节时用 |
| `{setVar:{entityType:"PlayerSelf",name:"Gold",value:10}}` | 写服务端自定义变量 |
| `{sendSignal:{name:"EarnGold",params:[1],target:"PlayerSelf"}}` | 发服务端信号 |
| `{view:2}` / `{pause}` / `{resume}` | 切视角 / 暂停 / 继续 |

`at` 省略 = 上一步 + `after`（默认 0.1 秒）；`drag` 占用的时间按 `(steps+1)×gap` 自动顶上。

**expect 断言八种**（引擎 `autotest/assert.js`；Host 侧还有一张**字段白名单**，见下）：

| kind | 参数 | 判什么 |
|---|---|---|
| `log` | `contains`、可选 `level`、`source:"server"`、`absent` | 客户端（或服务端）日志里出现过这段字 |
| `control` | `id?`/`name?` + `field` + `equals`、可选 `absent` | 控件字段等于某值（`text` / `visible` / `pressed` / `interactable`…） |
| `var` | `entityType` + `name` + `equals`、可选 `absent` | 服务端自定义变量等于某值 |
| `signal` | `name`、可选 `direction:"outbound"`、`values`、`absent` | 出现过该信号（可带参数） |
| `tree` | `name` + `exists`、可选 `absent` | 控件存在/不存在（**动态创建验证用这个**；只能按 `name` 找） |
| **`count`** | `name?`/`controlKind?` + `equals` 或 `atLeast` | **建了几个** —— `tree` 只能答「建了吗」，列表项/连击星这类要数数量的只能用它 |
| **`controlAbsent`** | `id?`/`name?` | 「这个控件**不该**存在」的语法糖（= `control{absent:true}`） |
| `lua` | `source` | 跑一小段 Lua 查询脚本，用 `query.var / query.control / query.logContains / query.logs / query.serverLogContains / query.serverLogs / query.signals` 自己判 |

**`absent:true`（2026-09-26 加）**：加在 `log` / `control` / `var` / `signal` / `tree` 上 = 「它**不该**存在」。
修它之前 `{"kind":"log","contains":"首错","absent":true}` 是**静默忽略** `absent`（引擎的
`autotest/format.js#normalizeAssert` 只搬运认得的字段）⇒ 变成「**必须**有这条日志」，于是断言"莫名失败"、
人/AI 去查一个不存在的逻辑问题。现在两处都通了：Host 校验字段 → 引擎搬运并**取反**判定。

**`kind:"lua"` 的返回值契约（实测，别照抄猜测）**：引擎 `evalQueryScript` → `runChunk` 走
`lua_pcall(L, 0, 0, 0)`（**要 0 个返回值**）⇒ **返回值被完全丢弃**：

```lua
-- ✅ 这样写才有判据：不成立就自己抛
assert(query.control("t1_kb_state") ~= nil, "状态控件没了")
-- ❌ 这样写**永远算过**（return false 也是过）
return false
```

也就是说：**脚本跑完不报错 = 通过**；要表达"不成立就失败"，必须自己 `assert(false, "…")` / `error("…")`
（报错文本会带回 `results[].message`）。语法错、跑挂也是失败。

**字段写错 ≠ 断言没过**：Host 侧有一张 `EXPECT_KINDS` 白名单（`lib/sim.mjs`），
`{"kind":"log","contians":"x"}` 这种会直接报**参数错**并列出该 kind 允许的字段
（旧版会静默忽略未知字段，让断言"莫名失败"）。

`at` 省略 = **最后一个事件之后 0.1 秒** ⇒ 查的是"这一串操作做完之后的最终状态"，**AI 不需要自己算时序**。

**失败长什么样**（AI 靠它自查，不用回头问人）：

```json
{"passed":false,"failedAt":0.1,"frame":3,
 "results":[{"kind":"var","ok":false,"actual":7,"expected":999,"at":0.1}],
 "hint":"第 1 条断言没过：kind=var 期望 999 实际 7（t=0.1s / frame=3）。看 results 与 snapshot.logs / serverLogs 定位，改完再跑一次 verify。"}
```

默认判定后**停掉会话**（不空烧 Worker 的 30FPS 时钟）；要接着交互就传 `keepRunning:true`。
⚠️ **失败取证会把会话置于暂停**（见 §4.8）——`keepRunning:true` 想接着玩，先 `op=play action=resume`。

> 写脚本要注意的口径（实测踩过）：服务端控件模板里 **`script.Parent` 是 nil**，按键监听正确写法是
> `script.object:AddKeyEventListener(Enum.KeyEventType.X, fn)`（引擎自己的 `runtime.test.mjs:548` 就这么写）。

## 4.7 写断言前先看控件（`op=controls`）

`op=state` 的每条 tree 行有 **12 个字段**（`ancestorIds` / `siblingIndex` / `siblingCount` / `templateId` / `guid` / `childCount` / `incomplete`…）——
对「写一条断言」这件事**全是噪音**。`op=controls` 只回**四个**：`{id, name, kind, depth}`，外加 `names`（可直接抄进 expect）、`kinds`（类型直方图）、`scripts`（已挂脚本）。

```json
{"op":"controls","namedOnly":true}
{"op":"controls","runtime":true}      // 看**运行中**会话的控件树（脚本运行时建出来的那批），需先 start
```

过滤参数：`namedOnly` / `nameContains`（**Host 侧过滤，中文可用**）/ `kind` / `maxDepth` / `limit`（截断回执带 `total`/`omitted`，不静默少给）。

**一条不显然但要紧的规则**（写在这里免得反复试错）：

| 断言 | 按什么找控件 |
|---|---|
| `expect[{kind:"tree"}]` | **只能按 `name`** —— 引擎 `findControl` 对 tree 只认 name ⇒ **没名字的控件断不了 tree** |
| `expect[{kind:"control"}]` | `id` / `name` 都认 |

`runtime:true` 与 `op=state` 的区别：前者是**跑起来之后**的树（脚本 `InstantiateClientUIControl` 建出来的会出现在这里），后者是编辑器工程树。
「哪些控件**能**被脚本动态创建」是另一个问题，问 `miliastra_map op=clientui`（只看无父节点的独立模板）。

⚠️ **两种树形状不一样（实测踩到，已拍平）**：

| | 形状 | 顶层条数 | 字段 |
|---|---|---|---|
| 编辑器树（`state` / `controls`） | **拍平** | 全部（带 `depth`） | 12 个（含 `ancestorIds`/`siblingIndex`…） |
| 运行时树（`controls runtime:true` / verify 取证） | **嵌套**（子控件在 `children`） | **只有 1 条**（「容器节点」） | 40+ 个（含 `box`/颜色/`text`/`instantiated`，**没有 `depth`**） |

`op=controls` 与失败取证都会**先拍平再数**——不拍平会把控件少算一个数量级（实测 **1 vs 17**）。
真实运行时的样子（demo 实测）：`容器节点 → [文本框, 光标检测区域, …, Lua实例化面板 → [模板标题, 模板图标, 确认按钮 → [按钮文字]]]`。

## 4.8 一组用例一次跑 + 失败自动取证（2026-09-24 补）

**① `cases[]`：把「一条规则一次调用」升级成「一次调用跑整组回归」**

```json
{"op":"verify","cases":[
  {"name":"按3加分","steps":[{"key":"KeyboardCraftspersonKey3Down"}],"expect":[{"kind":"log","contains":"SCORE_1"}]},
  {"name":"金币同步","steps":[{"setVar":{"entityType":"PlayerSelf","name":"Gold","value":7}}],"expect":[{"kind":"var","entityType":"PlayerSelf","name":"Gold","equals":7}]}
]}
```

→ `{passed, caseCount, passedCount, failedCount, cases:[{name,passed,failedAt,frame,results,logs?,runtime?,shot?}], failures:[{name,failedAt,hint}], hint}`

- 每个用例**各开一个全新会话**确定性重放 ⇒ **用例之间互不影响**（`tests/sim-test.mjs` 有一条断言专门钉这个：前一个用例按过的键**不会**漏进下一个用例）。
- 默认**跑完全部**（回归语义）；`stopOnFail:true` 则第一个不过就停，回执带 `stoppedEarly:true`。
- 通过的用例**不回 logs、不落图**（不给 AI 加噪音）；没过的回最后 10 行日志。
- `cases[i]` 缺 `expect` 时报错**点名第几个用例**，不是笼统一句。

**② 失败自动取证：`shot` + `runtime.controlNames`**（`shotOnFail:false` 可关掉存图）

`runCase` 的实现是「`playStart` → 在**活着的会话**上重放」，判定返回时会话**还停在失败那一帧**，所以能就地取证：

| 回执字段 | 是什么 | 怎么用 |
|---|---|---|
| `shot` | 失败点附近一帧 PNG（`sim-play-<用例名>-fail-<时间戳>.png`） | `read_image` 看一眼画面；**截图前先把 Worker 时钟 `pause`**，否则 30FPS 会继续往前走（`tickClock` 看 `status.paused`） |
| `runtime.controlNames` | 失败点附近的**运行时**控件名清单 | `tree{name,exists}` / `control{name,…}` 写错时，照着这份清单改期望值 |
| `runtime.controlCount` / `frame` / `time` | 计数与帧号 | 和 `failedAt` / `frame` 对一眼，确认取到的是不是同一处 |

⚠️ **诚实口径**：Worker 每帧 33ms，截图可能比 `failedAt` **晚 0~2 帧**——它是「失败点附近」的画面，不是逐帧精确的定点快照。

## 4.9 浏览器试玩页（W2）——**给人玩的**，但也是 AI 的一条路

`GET /miliastra/play`（面板「模拟器」页有「浏览器试玩 ↗」入口）。一页三件：**PixiJS WebGL 渲染的画面**、工具栏（开始/暂停/单步/重开/结束 + 设备·人数·视角）、侧栏（运行状态 / 服务端变量 / 日志 / **这一局的操作时间线**）。

**为什么需要它**（面板不是已经有 PNG 帧了吗）：面板是 **Host 出 PNG**，够 AI 看"画面对不对"，但人**玩**起来是 5fps 的幻灯片。
浏览器页让画面按 WebGL 真流畅地跑，手感、时序、连招这类只能人自己试的东西才有意义。

**技术形状**（三块，都是复用而不是新造）：

| 块 | 是什么 |
|---|---|
| 画面 | 引擎自己的 `engine/studio/play/pixi-renderer.js`（`PixiPlayRenderer`）+ `browser-session.js`（`createPlaySession`）—— **与上游 DSH 插件/Web 同一条浏览器循环**，搬引擎时就一起进来了 |
| 数据 | `POST /miliastra/engine`（与面板、与 `miliastra_sim` 工具**同一个入口**）⇒ 浏览器里玩的和 AI 操作的是**同一个会话、同一份工程** |
| 产物 | `node tools/build-sim-play.mjs` 用 esbuild 打成**单个 ESM**（552 KB，含 pixi）入库在 `lib/sim-play/dist/play-renderer.js` —— 装插件的人不做构建也能用 |

⚠️ **两个坑**（都已被测试钉住，别踩回去）：

1. **画面必须 `summaryOnly:false`** —— `scene` 是节点级增量场景，默认的"瘦身"会把它砍成 `sceneOmitted`（只留计数）⇒ 页面**黑屏**。
   修的是 `slimPlay`：原来**无条件**丢 `scene`/`paint`，与「summaryOnly 只去体积、`false` 时给全量」的约定矛盾。
2. **产物会过期** —— 改了 browser 侧源码却忘了重打包，页面在浏览器里跑的是**旧引擎**，而且**完全不报错**。
   `tests/sim-play-test.mjs` 现打一份比字节（`--check` 同款判据），`prepublishOnly` 也跑一遍。

### ★ 对 AI 的收益：人玩一局 → 那一局变成回归用例

这是这个页面**对 AI**（而不只是对人）的价值所在：

```
人在 /miliastra/play 里玩 → 报「刚才这么点就错了」
AI：miliastra_sim {"op":"verify","fromHistory":true,"expect":[{"kind":"var","entityType":"PlayerSelf","name":"Gold","equals":3}]}
→ 用**人那一局的真实操作序列**确定性重放 + 判定（AI 不用手抄 events）
```

所以页面**关掉时故意不停局**（`pagehide` 只 `destroy()` 渲染器）—— 一关就 stop 的话 history 归零，这条路就断了。
要停就点页面的「结束」，或让插件卸载（`disposeSimAll` 收干净）。代价是那一局会继续在 Worker 里以 30FPS 走，直到有人停它。

> ⚠️ **「确定回放」的边界**：`runCase` 会**重开会话**再重放 —— 所以 `fromHistory` 之后那一局就结束了；
> 而且它**不认 `device` 事件**（切设备那一步不会被重放）。

## 4.10 动画怎么证明（`op=frames`）★

`verify` 只能断言**某个静态值**（"t=1s 时 `matrix.tx=900`"）。但「动画到底动没动」「动的是不是那一块」这种问题，
两个值答不了 —— 而 AI 看不到动图。`op=frames` 把「两帧一样吗」变成**数字**：

```json
{"op":"frames","frames":[0,0.5,1],"steps":[{"click":{"x":800,"y":450}}]}
```

一次调用 = 按时间点出帧 + **帧间像素差** + **字段级变化**。实测（容器节点做 1 秒线性 Tween 右移 100）：

| 帧 | 文件 | 帧号 |
|---|---|---|
| t=0 | `sim-play-moving-t0-<时间戳>.png` | 0 |
| t=0.5 | `sim-play-moving-t0.5-<时间戳>.png` | 16 |
| t=1 | `sim-play-moving-t1-<时间戳>.png` | 32 |

```json
"diffs":[
 {"from":0,"to":0.5,"identical":false,"changedPixels":9704,"changedRatio":0.006739,"maxDelta":243,
  "bbox":{"x":452,"y":180,"width":737,"height":296},
  "changedControls":[{"id":"1","name":"容器节点","fields":{"matrix.tx":[800,850]}}]},
 {"from":0.5,"to":1,"changedPixels":9704,"bbox":{"x":502,...},"changedControls":[{...,"matrix.tx":[850,900]}]}]
```

**两个独立通道互相印证**（这是它比"只看图"强的地方）：

| 通道 | 读数 | 说明了什么 |
|---|---|---|
| 场景字段（`changedControls`） | `matrix.tx: 800 → 850 → 900` | **哪个控件的哪个字段**变了，能直接定位 |
| 像素（`changedPixels` / `bbox`） | 9704 px、bbox.x `452 → 502`（+50） | 画面**真的**跟着动了，且位移量与字段对得上 |

**负对照也验过**：换成静态工程后 `identical:true` / `changedPixels:0` / `maxDelta:0` / `changedControls:[]`
—— 所以那 9704 不是噪声。**可复现**：同一调用跑两遍，数字一样。

### 两条实现决定（改的时候别绕）

1. **内部用「暂停 + 单步」推进时间**：worker 自己有个 30FPS 的 `setInterval` 在走，不先 `pause` 的话时间会自己往前跑
   —— 帧就对不上时间点，也不可复现（面板的「单步」是同一个机制）。所以 `steps` 里的 `pause`/`resume` 对帧时间没有意义（Host 会把时钟重新冻住）。
2. **每帧回全量场景、由 Host 自己比字段**，不依赖引擎的增量协议。
   ⚠️ 位置**不在** `anchoredPositionX` 上 —— 运行时场景节点是 `{id,parent,z,group,matrix:{a,b,c,d,tx,ty},kind,name,…}`，
   所以「控件移动了」表现为 **`matrix.tx/ty` 变了**（不摊开 `matrix` 这一层，`changedControls` 会永远是空的 —— 实测踩到，已修）。

### 成本与边界（都是显式的，不静默）

- 帧数上限 **12**（每帧一张 PNG + 一次解码）；要推进的步数上限 **1200 步**（`dt` 默认 1/30 秒）——
  超了**直接报错并给出「换更大的 dt」这条路**，不会默默跑十分钟。
- `diff:false` 只出帧不比像素（省一次解码）；`threshold` 默认 8（每通道差值）。
- `bbox` 是**图像像素坐标（左上原点）**；舞台坐标是左下原点，两者 y 相反。
- 帧是**真落盘**的（不自动删，同 §5 纪律）；`keepRunning:true` 可以判定完接着玩，默认跑完就停。
- ⚠️ 帧文件名标签有 **24 字符上限**（`sanitizeLabel`）—— 写长了会把 `t0.5` 截掉（踩过；顺带修了「先剥尾点后截断又留下尾点」的 bug）。

## 4.11 交接值从哪来（`op=handover`）★ 2026-09-24 补

**它解决什么问题**：`bind` 最难的不是搭工程，而是**交接值**。抄错一位 → 脚本的 `InstantiateClientUIControl()`
**静默什么都不建**（不报错、日志里也没痕迹）。而创作者给的号通常就写在脚本常量里，所以"读源码抽真值"比"让人抄一遍"可靠得多。

```
① op=handover                         → 这台机器上有哪些活文件（★ 标出"当前正在开发的那张图"）
② op=handover source=<绝对路径>       → 读**那一份** .lua（活文件也行、桌面上任意一份 .lua 也行）：候选交接值 + suggestedTemplates + containerId
```

**双相实测输出（2026-09-24）**：

```json
[{"name":"CONTAINER_INDEX_HANDOVER","value":1073741866,"role":"container","isTemplate":false},
 {"name":"TEXTBOX_TEMPLATE","value":1073741867,"kindHint":"textbox","isTemplate":true},
 {"name":"IMAGE_TEMPLATE","value":1073741868,"kindHint":"image","isTemplate":true}]
"suggestedTemplates": [{...textbox 1073741867...}, {...image 1073741868...}], "containerId": 1073741866
```

- 判据：源码里的大整数赋值且值 ≥ `1073741824`（真机 id 的量级）——所以 `local LIMIT = 60` 不会被误收。
  **两种写法都认**（2026-09-25 补）：`local NAME = 1073741868` 与表字段/限定名 `prefabImage = 1073741852` /
  `CONFIG.prefabImage = 1073741852` —— 作者那份 `背景图片.lua` 就是后者，只认前一种时它的候选表是**空的**。
- ★ `source` 是**只读**的，且**复用 `miliastra_code op=read source=` 那同一套校验**：只认绝对路径（相对路径拒绝，
  免得按进程当前目录解析到别的文件）、> 8 MB 拒绝、二进制拒绝、非 UTF-8 拒绝。回执带 `readFrom:"source"` +
  `readOnly:true` + `readMeta`（bytes/lines/sha256_12/mtime/bom），`files`/`fileCount` 只是**顺带**列出这台机器上有哪些活文件。
  不传 `source` 时才走活文件扫描（`readFrom:"live"`，形状与以前一致）。
- 没抽到模板索引时回执带 `nextStep` **指路**：去 `.gil` 读（`miliastra_map op=clientui`）或手填 —— 不是一句"一条都没有"。
- `kindHint` **只看变量名**（IMAGE→image / TEXT→textbox / CONTAINER→role=container）：**控件类型猜错同样静默失败**，
  必须创作者确认。回执里明写这一点。
- 活文件清单**可能为空**（换了机器/账号）——如实回空，不报假警；给了 `source` 就只做抽取。

## 4.12 把真机那份工程搬进来（`op=bind`）★ 2026-09-24 补

**它解决什么问题**：模拟器能跑 Lua，但「让双相在模拟器里跑起来」原来是**手写试玩探针**（建模板 → 存盘 → 手改 JSON 里的 guid → 读回 → 挂脚本 → 起会话）。
这套流程里最容易错的不是技术，是**交接值**：模板索引错一位，脚本的 `InstantiateClientUIControl()` 就**静默什么都不建** —— 看起来"跑起来了"，其实全是空的。所以 `bind` 把这条路变成一个 op，并把交接值摆在明面上。

```
{"op":"bind",
 "source":"…\\Beyond_Local_Save_Level\\1073741833\\external_lua_file\\双相.lua",
 "templates":[{"guid":1073741868,"kind":"image","name":"图片模板"},
              {"guid":1073741867,"kind":"textbox","name":"文本框模板"}],
 "containerId":1073741866}
```

它做的四件事：

| 步 | 做什么 | 为什么这么做 |
|---|---|---|
| ① | `newAsset(client)` + 每个交接值 `addTemplate{guid,kind,name}` | **模板索引（= 顶层节点 guid）就是脚本里用的那个号**；引擎自己另编一个 ⇒ 永远解析不到。`addTemplate` 因此支持显式 `guid`（带合法性与重号校验） |
| ② | `newAsset(server)` + 挂脚本（挂载名 = 文件名，`scriptName` 可改） | 不少脚本用 `script.path` 自查挂载名（双相的 `checkMount()` 就要求 `双相.lua`）——名字不对它会**自己退出** |
| ③ | 交叉核对交接值 | 源码里 10 位以上的整数 ≈ 真机 id：`handover.missing` = 你交的模板索引在源码里找不到；`extra` = 源码里有、你没交的（可能还缺模板）。**启发式，不是判决** |
| ④ | 起一次会话、**先走 `settleSec` 秒再读** | 脚本的构建发生在**进入 RUNNING 之后**：停在 frame 0 读，双相只报 `controlCount=1`（容器自己）—— 会被误读成"什么都没建"（实测踩到） |

**默认值**：`fresh:true`（先把两个资产重置成出厂工程、清掉已有脚本，再重建 ⇒ 同一份参数 → 同一份工程）、
`keepFactory:false`（清掉出厂橱窗控件，否则它们混进渲染与控件清单）、`run:true`、`settleSec:0.5`。
`saveAs` 可把结果存进模拟器工作区；`mountTo` 指定挂在哪个控件上（默认服务端容器节点）。

**★ 2026-09-30 三处回执改动（AI 易用性反馈第 2/4/5/11 条，实测痛点）**：

| 参数 / 行为 | 是什么 | 为什么 |
|---|---|---|
| `runForMs`（新） | **真跑** N 毫秒再读：冻住后台 30FPS 时钟 → 按引擎固定步长（1/30s）**逐帧推进** `ceil(ms ÷ 33.33)` 帧；回执给 `run.runForMs` / `run.framesAdvanced` / `run.time` / `runMode`（**不是** `setTimeout` 睡觉）。范围 `0 < runForMs ≤ 60000`，超出**夹紧并如实标 `runForMsClamped`**（原值在 `runForMsRequested`）。跑完时钟**停在暂停**（画面/控件就是"跑到那一刻"，可复现），要它继续走时钟就 `op=play action=resume` | 作者的玩法 120 血、10~15 秒才出一次死亡，而 `settleSec` 只够看 3~8 秒 ⇒ 他**改了玩法数值去凑时长**，把整轮模拟跑歪了。⚠️ **两个都给时以 `runForMs` 为准**（`settleSec` 本次不生效，回执里写明） |
| `summaryOnly` 默认 | `op=bind` **默认精简档**：省掉 `sources[]`（逐条 sha1/mtime）/ `scripts[]` 逐条 / `mount.assetTypeNote` / `simAssumptions` 正文（留条数 + 指针）/ `note` 长段落；要全文传 `withMeta:true`（等价 `summaryOnly:false`）。**只去体积、不去结论** —— `handover` / `templates` / `run.controlCount` / `run.logs` / `kindHint` 一个不少，`omitted[]` 明说省了哪几样 | 作者一轮 `bind` 20+ 次、**每次 ≈15KB**，而他要的只有 `controlCount` + `logs` + 有没有 `lua-error` 三样 |
| `logScopeNote`（新） | `op=bind` / `op=play` 的回执**恒带**这一句：**这是模拟器日志（`snapshot.logs`，随时可读）；真机的 `.gia` 要等这一局结束才落盘，局中判画面只能截图（`miliastra_shot`）** | 两种模式来回切时不用在脑子里记两套取证路径 |
| `op=play action=step` | 回执**恒带 `note`**：**跑了 N 帧、时钟跳到 T；⚠️ `dt` 只跳时钟、不补跑中间逻辑**（N 是实测帧号差，不是"我们发了几次"）。`args.frames:<N>` = **真推 N 帧**（每帧 1/30s；推帧前**冻住后台时钟**，所以正好 N 帧、可复现，推完按调用前的状态还原）；`args.dt` = 老语义（一次性跳时钟）；两个都给 ⇒ **先帧后钟**，顺序写进 note | 作者以为 `step{dt:16}` 是"推进 16 秒游戏时间"，实际 `time` 跳到 16s 而只有 1 帧逻辑跑了（其余帧是后台时钟推的）⇒ 他为这条前后试了 **4 次调用** |
| `containerId` 台账 | 显式 `containerId` **优先于**台账；没给就看台账（`handoverFrom:"arg"` / `"ledger"` + `containerIdLedger` 记谁确认的）。两个都没有**不报错**（它只进交叉核对与配方，不参与搭工程），只给一句 `containerIdHint` 指路 | 台账里确认过的号不该每次再手抄。⚠️ **工具只读台账，绝不自动学**（写台账只有 `miliastra_health op=handover action=set` 那条显式路径） |

**★ 配方 `last-bind.json`（重启后一键重搭）**：`op=bind` 成功时会把它用的**源文件 + 交接值**记一小份配方到模拟器工作区。

### 4.12.1 `kind:"auto"`：控件类型**不猜**（2026-09-25 同事实测后加）

`kind` 一直是调用方猜的，而**猜错是静默的**：控件类型不对时脚本设属性会报
`cannot set <字段>, no such field` 并中止 —— 看起来"跑起来了"，其实**一个控件都没建**，
唯一的痕迹是脚本自己 `print` 的那行。所以给了两条兜底：

| 情形 | 回执 | 说明 |
|---|---|---|
| 传 `kind:"auto"` | `kindTried[]` + `kindWinner` | 按 **image → textbox → container** 逐个**重建模板工程并起一次会话**，判据只有一个：**控件数有没有增长** |
| 不传 auto、控件数又没涨 | 自动附一条 `kindHint` | 「可能一个控件都没建出来……可试的候选：image / textbox / container，或传 `kind:"auto"`」 |

**基线是编辑器工程里的控件数**（回执的 `editorControlCount`，也是 `kindTried[].baseline`）：
运行时树拍平出来的那批正好就是它（实测 fresh 时两边都是 1、keepFactory 时两边都是 11），
所以「`run.controlCount` 没有比它大」=「脚本一个控件都没建出来」。
`auto` 选中 winner 的那一局**直接当这次 `run` 用**（不重复跑）；一个候选都没涨就落回第一个候选并给 `kindHint`。

### 4.12.2 `mount` 回的是**真实层级**（别被 `assetType` 误导）

同事实测：`mount.assetType: "server-control-template"` 让人以为脚本挂错了地方 —— 而 `op=controls` 里的真实拓扑是
`客户端控件容器(server-container) → 容器节点(container)`：**真机上客户端脚本就是挂在客户端控件容器的那个容器节点上**。

所以 `mount` 现在给 `parent:{name,kind}` / `ancestors[]` / `isClientUI` / `clientUIRoot`；
`assetType` **保留**（兼容）但加了一句 `assetTypeNote`：它只是**控件模板资源**的名字
（模拟器里"服务端那份工程"），**不代表"挂在服务端"**。

## 4.13 验收单（`op=cases`）★ 2026-09-24 补

**它解决什么问题**：`verify` 是一次性的（跑完就没了），而"这一版该怎么验收"是**要沉淀下来**的：
下次改完，人还是照上次那套点，AI 还是照上次那套断言 —— 否则每次都在重新定义"算不算过"。

清单存在**模拟器工作区的 `cases.json`**（`<dataRoot>/simulator/cases.json`，不碰游戏存档），人和 AI 读**同一份**：

| action | 做什么 |
|---|---|
| `list`（默认） | 每组一行：`autoCount` / `manualCount` / 每条用例的 `kind`（auto / manual）+ 事件数 + 断言数（**不给全量 events，省 token**） |
| `show` | 某一组的用例全文（要抄/要改的时候用） |
| `add` | `set=<名字>` + `cases:[{name,steps,expect}]`；**同名 = 覆盖**（改断言再存一遍）。加 `fromHistory:true` 就把**刚跑过那一局**的操作变成用例（AI 不用手抄 events）。`{manual:true, note:"…"}` = 人工项 |
| `run` | 自动项走 `verify` 的确定性重放；**人工项不代跑**，只列进 `manual[]` 等人打勾。可按 `cases:[名字]` 只跑其中几条 |
| `remove` | 默认 **dryRun**（只说会删什么）；真删要 `confirm:true` |

**两条纪律写进回执里**：

1. **`autoPassed` ≠ 验收通过** —— 返回里直接写「自动项已跑完（2/2）—— 但**整组没算过**：还有 N 条人工项要人确认」。
2. **人工项不写 `note` 就报错** —— note 是"人要看什么、看到什么算过"，没有它这条单子等于没写。

`op=verify caseSet=<名字>` 也能直接跑清单里那一组（人/AI 同一份入口）。

## 4.14 AI 自己"玩"到底能到什么程度（2026-09-24 实测，全是数字）★

作者问「你能在模拟器中游玩吗」，于是**当场量了一遍**（真机关卡《冰镜·火烛》，出厂工程/真机工程各一遍）：

| 量什么 | 实测 | 含义 |
|---|---|---|
| 发一次输入（`key` / `pointer` / `click`） | **p50 4.6ms / max 25ms**（40 次） | 纯注入、不回快照 ⇒ **发得快** |
| 读一次 `get{view:true}`（含场景） | **≈216ms** | 我的"眼睛"= **≈5Hz 离散采样**，不是 30fps 视频流 |
| 出一张 PNG（`op=shot`） | 秒级 | 视觉是"拍照片"不是"看视频" |
| 静置时引擎时钟 | 2.528s 墙钟 → **+2.600s / +78 帧 = 30fps** | 时钟**自己走**（②档"实时"名副其实） |
| 连续注入期间 `frame` | 2.207s 墙钟 → **+92 帧 = 41.7/s** | ⚠️ **注入会顺带推帧** ⇒ `frame` **不是秒表**，计时用 `time` |
| 负对照（无输入 700ms） | 场景里**没有任何节点在动** | 所以"动了"确实是输入造成的 |
| 实际操作效果 | 6 个小节点（4×11 / 8×14，小人是拼出来的）同步 **Δx=+138.7**；画面像素差 **2382/1 440 000 = 0.17%**，bbox `x 37..203, y 54..107` **正好是小人那片** | 按右 = 真走，且游戏自己的日志写下了 `收到首个按键事件: KeyboardMoveRightKeyDown（来源=KeyEventType）` |

**三种玩法**（能力差别很大，别混）：

| 玩法 | 能不能 | 怎么做 | 代价 |
|---|---|---|---|
| ① 回合制闭环 | **能，完全可控** | `pause` → 发一步 → `step` → 读场景 → 再决定 | 一步 = 一次模型往返（秒级） |
| ② 实时档打一段 | **能** | **一次调用里跑循环**（本地往返 5ms 级，能跑满 30fps），判断写成循环内条件分支 | **循环里看不见**；事后靠 `history` 快照/PNG 取证 |
| ③ 确定性演一遍 | **能，可复现** | `verify` / `cases` / `fromHistory` | 时间点**预先写死**，不能边玩边变 |
| ✗ 逐帧看画面再反应 | **做不到** | —— | 带宽上限（≈5Hz），不是"没实现" |

**两条只有实测才会知道的坑**（现已写进 schema，AI 不会自己猜出来）：

1. **`op=keys` 漏检裸字符串键名**（2026-09-24 修）：旧实现只认 `KeyEventType.X` / `["X"]`，而真脚本是
   `bindHold("KeyboardMoveRightKeyDown", …)`，于是回「脚本源码里没出现 `KeyEventType`」—— **把原因说反了**
   （名字出现在候选表里，只是写法不匹配），AI 据此只能**猜**键名，而猜错是**静默失败**。
   现在两路都扫、每个名字带 `via`（`enum-member` / `enum-index` / `string-literal`），
   注释掉的绑定不算（`stripLuaComments` 是**认字符串**的，不会把 `"a--b"` 当注释截断）。
   真身验证：`双相.lua` 扫描结果 **0 → 25 个键名**（方向/跳跃/交互/工匠键 + 手柄键 + `CharacterSkill3`）。
2. **按了 `…Down` 必须配对发 `…Up`**：引擎的键事件是"按下/抬起"两件事，只发 Down 等于**一直按住** ——
   实测把小人一路推到**掉出边界重生**。`op=keys` 的 `found[]` 里 `Down`/`Up` 是成对列出来的，照抄即可。

> ★ **读画面上的字用 `op=hud`**（2026-09-24 新增）：只回 `textbox` 的 `text` + **世界坐标**，别为了读 HUD 去 dump 整个场景。
> 实测（真机《冰镜·火烛》在跑的那一局）：`get{view:true}` 的快照 **30 177 B / 31 个节点**，
> 而 `hudTexts()` 从里面只挑出 **2 行**：
> ```
> id=15  world=(800,866)  「第1关 教学  (1/3)   分数 0   当前：冰境    跳跃=切相」
> id=16  world=(800,824)  「方向键 / A D 移动，空格 / ↑ 跳跃（跳跃即切相）」
> ```
> ⇒ 回执 ≈300 B，**省掉约 100×**；坐标是沿 `parent` 链累加出来的**世界坐标**（局部 `ty=374` + 容器 `450` = `824`）。

> ★ **"屏幕上有哪些控件、在哪、上面什么字"一次拿**：`op=controls {runtime:true, geom:true}`。
> 每行加 `x/y`（**世界坐标**，左下原点，可直接喂 `pointer`/`click`）+ `w/h` + `text`。
> 底层是**一次** `get{inspect:true, view:true}`（引擎里 `inspect` 与 `view` 是**独立填充**的，能同时给），
> 但摊平后**只回紧凑行**：实测回执 **1.4 KB**，而那次底层响应是 **75 KB**（tree + 31 节点场景）。
> ⚠️ 实测挖出一个**真事实**：**场景 ≠ 控件树** —— `scene` 只含**会被渲染**的控件（工厂默认工程 `tree` **11** 行 / `scene` **5** 个节点；
> 真实关卡 `双相` 是 31/31）。所以回执带 `geomCovered` / `geomMissing`，并且明说
> **"没坐标 ≠ 不存在，只是现在不在画面上"** —— 否则 AI 会把"不可见"误判成"没建出来"。

> ★★ **「找个按键这么久」的教训（作者原话）——请求形状属于 schema，不该让 AI 读实现**：
> 我知道键名之后，为了知道 `play` 的 `key` 怎么发，翻的链路是
> `session.js`（`injectPlayKey`）→ `browser-session.js`（`act('key',{key:name})`）→
> `controller.js`（`play(action,args)` 原样转发）→ `worker.js`（`studio.playKey(args.key,{observe:false})`）**4 个文件**。
> 现在两处一次说清：① schema 里写了量级与 `op=hud`；② **`op=keys` 的回执直接带 `press`** ——
> `key` / `pointer` / `click` / `step` / `hud` 的**可照抄请求体**（`{"op":"play","action":"key","args":{"key":"…"}}`）。
> 同一件事还留了两条绊线：`smoke` 断言 schema 里必须有 `press` 与 `op=hud`；`sim-test` 断言 `press` 的五个形状别退化。

## 4.15 网格计算页（第六个 tab，2026-09-30）

> **它解决什么**：真机 UGC 画布是 **1600 × 1000**，所有坐标都按它设计；**摆放模型时对不准位置**。
> 所以按网页设计里"网格"的思路做了这一页：**给人（和玩家）算坐标**，不参与任何运行时逻辑。
> **纯前端计算** —— 一个工具都不调、不写任何文件、不碰活文件（因此它没有"失败态"，唯一会错的是输入本身）。

### 规则相对工作区技能 `game-grid-mapper` 改了两条（作者 2026-09-30 定）

| # | 旧（`game-grid-mapper/grid.py`） | 新（本页） |
|---|---|---|
| ① | **必须整除**：不整除直接 `ValueError` 拒绝建档（"110 在 1600×1000 上残 60px，不合法"） | **不要求整除**：如实报「残 N px」，并**把界外那一条（残格）丢掉** —— 网格只覆盖 `cols*stepX × rows*stepY` |
| ② | 只有一个正方形 `cell` | **X / Y 步长可以不同**（默认推荐 **X 100 / Y 50**） |

作者给的例子：`1600×1000 / X110 Y80` ⇒ X `1600/110 = 14.5455` 残 60px、Y `1000/80 = 12.5000` 残 40px
⇒ **网格 = 14 × 12 = 168 格**，有效覆盖 `x[0,1540) y[0,960)`；落在右边 60px / 下边 40px 里的点**不算**（原话：「我们就不管最后在界外的点了」）。

### 三个态（像素 → 格）

| `state` | 含义 | 面板怎么说 |
|---|---|---|
| `in` | 落在某一格里 | `✅ 格 (8, 5) 覆盖 x[880,990) …` |
| `rest` | 落在**残格**里（画布内、但网格切不到） | `⚪ 界外（残格）不算 —— x 1550 落在第 15 格位置上（网格只有 14 格，到 1540）` |
| `out` | 画布外（含正好落在右下边界上的点） | `⚪ 界外（画布外）不算 —— 画布只有 1600 × 1000` |

★ **界外的点不给"格号"**（`col`/`row` 回 `null`，只给 `colRaw`）—— 编一个邻近格号正是"看着对、其实差一格"的来源。

### 坐标口径（别混用）

本页 = **设计画布**：左上 `(0,0)`、x 右增、**y 下增**（与 `game-grid-mapper` 一致）。
⚠️ 模拟器内部舞台（`stagePointFromEvent`）是**左下原点、y 向上**，那是引擎那一层 ——
`client-render-test` 里有一条**反向绊线**：网格图的取点必须是 `clientY - rect.top`，**不许**出现 `rect.bottom - clientY`。

### 防呆与上限（都是显式的，不静默）

- 步长 `1px` ⇒ 160 万格：**不画格线**（每条轴 > 200 条就只画边界）、**不建速查表**（> 200 格），但**数字照给**并说明原因。
- 参数不合法（宽高 ≤ 0 / 非数字 / 步长比画布还大）⇒ 如实报错，不抛、不静默兜底。
- 「点图取坐标」的线性换算前提是**盒子比例 == viewBox 比例** —— CSS 里 `-gridsvg` 是 `width:100%;height:auto`（比例由 `viewBox` 定），
  再加 `preserveAspectRatio:"none"`，所以盒子里没有留白。**改这条 CSS 就会让取点失真**（回归里钉住了 `width:100%`）。

### 格内灰字坐标 + 选中/复制（2026-09-30 作者要求：「每一格灰字展示经纬度；选中一个高亮，并且能复制」）

| 档 | 格内画什么 | 例子 |
|---|---|---|
| `center`（**默认**） | 该格**坐标** `x,y` —— ★ **与「取哪一角」联动**（默认右下） | `900,550`（右下）/ `800,500`（左上） |
| `cell` | 格号 `col,row` —— 网格自己的"经纬度" | `8,10` |
| `off` | 不画 | —— |

> ★ **2026-10-01 作者：「网格图的 xy 应该要和 取哪一角 联动」**：坐标档显示的**就是**「选中的格」那一行下拉选的那个角。
> 按钮名字里把当前角写出来（`坐标 x,y（右下）`），换角时格内灰字立刻跟着变。
> ⚠️ 内部 id 仍叫 `center`（**只为老缓存能继续用** —— 改 id 会让已经存过的值静默回落成默认）。

- 字号按**格子的实际大小**算：宽 ≤ `stepX × 0.9 / (最长文本长度 × 0.58)`（左右各留 5%）、高 ≤ `stepY × 0.62`，再夹到 ≤48，
  **向下取整到 0.1**（四舍五入会把字号顶到上限之上，那就不"塞得进"了）。
  ⚠️ 用**真实最长文本长度**：联动到角以后文本会变长（中心 `'50,25'` → 右下 `'1600,1000'` 是 **9 个字符**），
  拍一个固定的"每字符系数"会让标签**越到邻格里去**。
  ⚠️ **字太小（<14）或格太多（>600）就不画**并**如实说明**（画出来是糊的 = 骗人 —— 与"线太多不画线"同一条纪律）。
- 点任一格 ⇒ **吸附到该格中心**并选中（像素 x/y 与列/行**一起填**，左右两张卡不会各说各话）；
  点在**残格 / 画布外**时**不吸附**（照实填那个点），好让"界外"这条判定能被亲眼看到。
- 选中那格：粉块高亮 + 它的标签**变亮粉加粗**；**图下面一行写清选了哪一格**
  （`已选中：格 (8, 10)　覆盖 x[800, 900) y[500, 550)　左上 (800, 500)　中心 (850, 525)`），
  旁边就是**「复制选中的格」**；没选中（残格 / 画布外）时按钮**禁用**——而不是让人点了才被告知没选中。
- 标签组带 `pointer-events:none`：戳到文字也算戳到图（不会因为戳到文字就没反应）。

### 多选 / 列表 / 四角 / 一起复制（2026-10-01 作者要求）

- 点一格 = 把那一格**加进/移出**选中（可连点多个 —— 这就是"多选"）；选中的格**全部**粉块高亮、格内标签变亮粉加粗。
- 图下面一张**列表**：一行一个格 + 每行「复制」「移除」；
  上面一行是**四角下拉**（`右下`默认 / `左下` / `左上` / `右上`）+「复制全部（x,y 列表）」+「清空选择」。
- **四角**决定复制出去的 `x,y` 取这一格的哪个角（纯函数 `gridAnchorPoint`；未知值回落成**右下**）。
  列表每行标明用的是哪个角：`1. 格 (8, 10)　右下 {x = 900, y = 550 }`。
- **一起复制的格式照作者给的**（回归里**逐字节**对过）：

  ```
  [{x = 730, y = 460 },
  {x = 840, y = 540 }]
  ```

- ⚠️ **网格改小后失效的格**（原来选了第 15 列，现在只有 14 列）**留在列表里说清原因**（`⚠️ 没有这个格：列 0~13…`），
  只是**不参与复制** —— 既不静默丢掉、也不拿邻近格顶替（那正是"看着对、其实差一格"的来源）。
  ★ 出现这种行时，按钮行会多出一个 **「移除失效行（N）」**（纯函数 `gridSelPrune`）—— 一键清掉，列表立刻又能复制了。
- 复制的结构是纯函数 `gridSelLua(rows)`；列表行是 `gridSelRows(plan, sel, anchor)`；点格切换是 `gridSelToggle(sel, col, row)`
  （**不改入参** —— 就地改 React 状态会改坏渲染）。三个都单独回归。

### 网格图的缩放 + 左键拖动平移（2026-10-01 作者要求）

- ★ **Ctrl / ⌘ + 滚轮 = 缩放**（缩放的**唯一**入口）；旁边那颗按钮是读数 + 复位（`缩放 100%`，点一下回 100%）。
  范围 **50% ~ 800%**，值进缓存（**读缓存时也过一遍夹取** —— 老版本存过的 29% 会在打开时抬到 50%）。
- ⚠️⚠️ **普通滚轮一律不缩放**（2026-10-01 作者反馈后改成这个口径：「这个滚轮咋把网格图也搞小了」）：
  原来"光标在图上一滚就缩放"是个**滚轮陷阱** —— 人想往下滚面板 / 滚列表，光标正好停在图上，图就被缩到 29%。
  现在普通滚轮**不 `preventDefault`**，浏览器照常滚那个盒子（图放大后）或滚面板；只有按住 Ctrl/⌘ 才缩放。
  ⇒ 回归里钉住：`if (!e.ctrlKey && !e.metaKey) return;` **必须排在 `e.preventDefault()` 之前**。
- **左键按住拖动 = 平移**（作者：「网格图 放大后我希望能左键按住拖动」）：拖的是图那个滚动盒子的 `scrollLeft/scrollTop`，
  拖动时手型 `grabbing`。与"点一格 = 选中/取消"共存的办法：
  **位移 > 3px 才算拖**，拖过之后**把随后那次 `click` 吃掉**（`suppressClick`）—— 否则拖完松手会顺手多选/取消一格。
- ⚠️ **每次 mousedown 先清零 `suppressClick`**：不然"在图上拖完、鼠标松在格子外面"时 `click` 打不到 SVG，
  标记会留到下一次 ⇒ **下一次真正的点击被白吃一次**（"第一下点了没反应"）。
- ⚠️ **滚轮必须用原生非 passive 监听**：`addEventListener('wheel', fn, {passive:false})`。
  React 的 `onWheel` 是挂在根上的 **passive** 监听 —— 在里面 `preventDefault()` 不生效（浏览器警告，
  且 **Ctrl+滚轮会把整个网页缩放掉**）。
  这是本页**唯一**一处在 React 之外挂 DOM 监听的地方，回归里钉住「不许出现 `onWheel:`」。
- 点图取坐标**不受缩放/平移影响**：换算用的是 SVG 自己的 `getBoundingClientRect()`（它跟着滚动走），
  所以放大/平移之后**点哪还是哪**；`preserveAspectRatio:"none"` + `width:<zoom>%` 保证盒子比例仍等于 viewBox 比例。
- 图外面是 `-gridbox`（`overflow:auto` + `max-height:min(420px,52vh)`）：放大后由它出滚动条，不然图会一路把面板撑长。

### 右键标记颜色（2026-10-01 作者要求：「右键标记颜色…导出时候可以直接带 color」）

- 色板 **8 色**：`灰(#d6d7dc) / 红 / 橙 / 黄 / 绿 / 青 / 蓝 / 紫` —— **第一色就是作者例子里的那个灰**。
  点一个方块当**笔刷**（当前笔刷打勾），图上**右键点格** = 用笔刷上色；**同一个色再右键一次 = 清除**；另有「清除标记」（只清颜色，不动选中）。
- 标记的格在图上画成**半透明色块**（`fill=<hex> fill-opacity=0.45`，画在格线之上、选中粉块之下）；
  右键标记时**保证那一格在选中列表里**（不然导出列表里看不到它）。
- ⚠️ **右键标记绝不改变选中状态**：用的是 `gridSelAdd`（**只加不减**），**不是** `gridSelToggle`；已在列表里就原样返回。
  —— 用 toggle 的话，"给一个**已经选中**的格标颜色"会把它**踢出**选中 ⇒ 列表变 0、复制按钮全灰，
  也就是作者 2026-10-01 报的「我点了一次之后就不让复制了」。回归里钉住"右键那段不许出现 `gridSelToggle`"。
- 导出片段**逐字**照作者给的例子（回归里**逐字节**对）：

  ```
  [{x = 330, y = 560 ,color="#d6d7dc",colorName = "灰色"}]
  ```

  没标颜色的格照旧 `{x = 330, y = 560 }`；两种混着来也各自正确（颜色只加在标过的那几行）。
- 纯函数：`GRID_COLORS` / `gridColorById` / `gridColorToggle`（切换、不改入参、未知色当清除）/ `gridColorOf`；
  色板、笔刷、标记都进缓存（键 `dsh-miliastra:grid`）。

## 4.16 模拟器的「会话」：一份工程 vs 多份独立工程（2026-10-01）

Host 的模拟器**本来就按会话分控制器**：`lib/sim.mjs` 的 `registry` 用键 `ctx.sessionId`（缺省 `'default'`）
各自持有 `SimulatorController`（各自一个 Worker、各自一份内存里的工程）。以前面板与 AI 都传空 ctx ⇒ 大家共用 `'default'`。

| 入口 | 会话 | 说明 |
|---|---|---|
| `POST /miliastra/engine`（不带 `__session`） | `default` | 模拟器页、像素画页、AI 的 `miliastra_sim` —— **共用同一份工程**（要的就是这个：AI 投进去、人能在页面上玩） |
| `POST /miliastra/engine`（带 `__session`） | 该名字 | 会话名只认 `[A-Za-z0-9_-]{1,32}`，别的当默认；`__session` 会从 args 里**摘掉**（引擎看不见它） |
| `GET /miliastra/play` | `default` | 浏览器试玩页（`?session=<名>` 可指定；Host 把名字盖进页面：`window.__MILIASTRA_SESSION__` + 页脚 `· 会话 <名>`） |
| **预制效果页** | `presets` | 预览 `op=bind` 走 `/engine` 带 `__session`、画面挂 `?session=presets` ⇒ **与上面那份互不影响** |

> ★ 为什么预制效果要独立：它的"预览"是**反复 bind 新工程**（切预设就重投一次），跟 AI 正在跑的工程抢同一份状态时，
> 两边都会莫名其妙地变（作者 2026-10-01：「我希望预制效果的模拟器是独立的，不受到其他影响」）。
> ⚠️ 代价：多一个 Worker；且 `op=save` / `op=load` 这类**落盘**操作共用同一个工作区目录（预设名可能撞，用之前想一下）。
> ⚠️ **工具侧没有会话参数**（`miliastra_sim` 的 schema 里没有 `session` —— 它永远是默认会话）；
> 面板要独立会话只能走 `/engine` 这条路，这也是预制效果页**不再用工具**做预览的原因。
## 5. 三条安全纪律（改动时别绕）

1. **用户 Lua 一律跑在可终止的 Worker 里**（引擎自带的 `worker_threads.Worker`，默认单次操作 8 秒超时后 `terminate`）。
   实测：塞一段 `while true do end`，`play start` 在超时后**返回错误**而不是挂住，随后 `stop` 仍可用（`tests/sim-test.mjs` 有断言钉住）。
   意义：控制台/Web GUI **不会**被一条失控脚本冻死。
2. **工作区固定在本插件数据目录下的 `simulator/`**（`<dataRoot>/simulator`）—— 模拟器的存档读写只发生在这里，**永不指向游戏存档、地图或活文件目录**。
3. **插件卸载/重挂时 `disposeSimAll()`** 收掉所有会话的 Worker，不留幽灵进程。

> 工具 schema 是**每个会话都在花的钱**（`tests/smoke.mjs` 里有 32 KB 棘轮）。这一轮把

### 1. `op=verify` 的完整形状（schema 里只留了 kind 名与指针）

- `steps[]` 每步：`at`（模拟秒；省略 = 上一步 + `after`，默认 0.1s）/ `after` / `key` /
  `click{x,y}`（**左下原点**）/ `clickName` / `drag{from,to,steps?,gap?}` / `pointer{type,x,y}` /
  `setVar` / `sendSignal` / `view` / `pause` / `resume`。
- `expect[]` 每项 `{kind, at?, …}`，八种 kind 与各自字段：
  `log{contains,level?,source?}` / `control{id?|name?,field,equals}` / `var{entityType,name,equals}` /
  `signal{name,direction?,values?}` / `tree{name,exists}` / `count{name?,controlKind?,equals|atLeast}` /
  `controlAbsent{id?|name?}` / `lua{source}`。
  `absent:true` 可加在 log/control/var/signal/tree 上 = 「**不该**存在」；`tree` 只按 `name` 找；
  问「建了几个」用 `count`；**未知字段会当参数错报出来**（不是断言没过）。
- `lua` 断言的契约：**返回值被忽略** —— 脚本跑完不报错就算过（`return false` 也算过）；
  要"不成立就失败"得自己 `assert(false, "…")` / `error("…")`。可用 `query.var/control/logContains/logs/serverLogContains/signals`。
- 回执：`passed` / `failedAt` / `results[]`（ok·actual·expected）/ `snapshot.logs`；

  不要取证传 `shotOnFail:false`；`fromHistory` 回放会**重开会话**，`keepRunning:true` 保留会话接着 `op=play`。
- 一组一次跑：`cases:[…]` 各自开新会话重放（可当回归套件），默认跑完全部，`stopOnFail:true` 第一个不过就停。

### 2. `op=handover` / `op=bind`（交接值）

- `op=handover`：列出这台机器上的**活文件**（标出"当前正在开发的那张图"）与候选交接值
  （`local NAME = <9 位以上整数>` / 表字段都认，含 `kind` 提示）+ `suggestedTemplates`；
  也可带 `source`（**任意本地 .lua 绝对路径，只读**：>8 MB / 二进制 / 相对路径一律拒绝，读完零改动）。
- **guid / containerId 优先自动拿，拿不到才问创作者（不许编）**：① handover 抽 → ② `miliastra_map op=clientui` 读 → ③ 才问人。
- `op=bind`：搭好模板与脚本，默认起一次会话并回 `run.logs` 与 `run.controlCount`；
  `fresh:true`（默认）清空出厂橱窗控件、`run:false` 只搭不跑。
  **`kind` 猜错是静默的** ⇒ 拿不准传 `kind:"auto"`（按 image → textbox → container 逐个起会话，
  谁让控件数增长就用谁，回执 `kindTried[]`/`kindWinner`；控件数没涨会自动附 `kindHint` 点破）。
- `mount` 回**真实层级**（`parent`/`isClientUI`）：真机客户端脚本挂在 `客户端控件容器(server-container) → 容器节点(container)`；
  `assetType` 只是**控件模板资源**的名字，**不代表"挂在服务端"**。
- ⚠️ **Host 是启动快照**：重启 `dsh web` 后内存里的工程回到**出厂默认**（`op=state.factoryDefault:true` 会说）；
  成功 bind 记一份配方（`last-bind.json`），`{"op":"bind","last":true}` 一键重搭。

### 3. `op=cases`（验收单）

`action=add set=<名字> expect=[…]` 存自动用例（加 `fromHistory:true` 就把刚跑过那一局的操作变成用例）；
`manual:true, note:"人要看什么"` 存**人工项**（`name` 缺省取 `note` 前 20 字）；
`action=run set=<名字>` 重放自动项并列出 `manual[]` 等人打勾（`autoPassed` **不等于**验收通过）；`list/show/remove` 看/删。
`op=verify caseSet=<名字>` 也能直接跑那一组。

### 4. `op=patch` 的字段白名单（传错名会报错点名，旧版会静默忽略）

- `add` 支持 `text`（`{"op":"add","kind":"textbox","name":"t","text":"…"}` —— 建的时候就带上；旧版 `text` 被吞、inspector 里永远是空串）；
- `add` 也支持 **`imageId`**（2026-09-30 补，**只给 `kind:"image"`**）：
  `{"op":"add","parentId":"n1","kind":"image","name":"方块图","imageId":100001}` ⇒ 回执 `imageIdApplied:{id,imageId}`。
  为什么需要它：模拟器现在**不再替图片控件补方块**（模板没给贴图就画 `?`，与真机一致，见 §E1③）——
  「我就想要一块有色方块」于是没了入口，这条把它补回来（建好之后补一次 `set key=imageId`）。
  不给 `imageId` 的新图片控件就是 **0 = 未指定**（画 `?`）。传给别人 kind（如 textbox）会**明确报错**，不静默忽略。
- `set` 要 `{op,id,key,value}`（传了 `field` 会提示你是不是想传 `key`，并列出该控件可设的 key）；
- `remove` / `setCanvas` / `addScript` / `updateScript` / `removeScript` 各自的字段也校验；
- `addScript` 要 `source` 或 `sourceFrom`（.lua 绝对路径，**都不给会明确拒绝**，不写空脚本），`updateScript`/`removeScript` 支持 `path`；
- `op=bind` 可一次挂多个：`scripts:[{path, source|sourceFrom}]`。

### 4.1 存档：`op=save` / `op=load` / `op=reset`（含 2026-09-30 的体积修正）

- `op=save` ⇒ 写进**模拟器工作区**（`<数据目录>/simulator/`），回执 `{path,bytes,revision,name}`；
- `op=load`（不给 `archive`）⇒ **列出**工作区里的存档；
- `op=load archive=<名>` ⇒ 读回工程。★ **`summaryOnly:true` 会省掉整份快照**：
  默认档回执里带 `result.snapshot`（**整份存档，实测 1.0 MB** —— 一次会话能连吃两发）；
  传 `summaryOnly:true` 后只回结论（`resultSummary:{hasSnapshot,warnings,metadata,scripts[]}` + `resultOmitted` 说明），
  实测掉到 **2 KB 量级**。**默认行为没变**（要看正文就不传），所以两边都不少东西。
- ⚠️ **模拟器的"当前工程"是内存态**：**重启 `dsh web` 后会回到出厂演示工程**
  （`op=state` 会报 `factoryDefault:true`，看起来像"什么都没画"）。要留住工程就 `op=save`；
  面板顶部有提示 + **一键重搭上次**（配方 `<数据目录>/simulator/last-bind.json`，成功 `bind` 时自动记）。

### 5. 「AI 自己玩」的其余口径

- `op=keys` 从**你的脚本源码**扫按键名（**两路**：`KeyEventType.X` 与**裸字符串** `bindHold("KeyboardMoveRightKeyDown", …)`；
  `found[].via` 标来源，`string-literal` 是启发式）；回执带 **`press`**（`key`/`pointer`/`click`/`step`/`hud` 可直接照抄的请求体，指针**左下原点**）；
  传 `all:true` 给**全量 164 个键名**（`Enum.KeyEventType`，≈3KB；默认 10 条 presets）。
- `op=hud` 只回 `textbox.text`（HUD/分数/关卡 + 世界坐标），拿它当闭环条件；别为两行字 dump 整个场景。
- 量级：发一次输入 ≈ **5ms**（`key`/`pointer`/`click` 纯注入、不回快照），读一次 `get{view:true}` ≈ **200ms**，出一张 PNG 秒级 ⇒ 眼睛 ≈5Hz。
  ① 回合制闭环（`pause`+逐步 `step`+读场景）完全可控；② 实时档打一段要在**一次调用里跑循环**（循环里你看不见，判断写成循环内分支、事后用 `history`/PNG 取证）；
  ③ **逐帧看画面再反应做不到**。
- ⚠️ `frame` **不是秒表**：连续注入按键会顺带推帧（静置 30fps、注入期间 41.7/s），要计时用 `time`。
- ⚠️ 用户 Lua 跑在**可终止的 Worker**（默认 8 秒超时 terminate）；工作区固定在插件数据目录的 `simulator/`，不碰存档、地图与活文件。
- `op=frames`：`frames:[0,0.5,1]` → 每点一张 PNG + 帧间像素差（`changedPixels`/`changedRatio`/`bbox`）+ 字段级 `changedControls`
  （哪个控件的哪个字段变了，如 `matrix.tx: 800 → 850`）；内部「暂停+单步」⇒ 可复现。
- `op=controls`：`{id,name,kind,depth}` + `names` + 类型直方图（最省 token）；`runtime:true` 看运行中会话里脚本动态建出来的，`geom:true` 给世界坐标/源尺寸/文字。

### 6. 模拟器**不模拟**的那一条（重要边界）

真机铁律：**文本框矩形高不够 ⇒ 该控件一个像素都不画**。模拟器**不模拟**这个截断，
所以那条判据只能在离线用 `miliastra_code op=lint-ui` 拦（见 `docs/功能详解.md` §UI 门禁）。
