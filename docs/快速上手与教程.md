# 快速上手与教程（安装 / 面板 / 常见坑 / 发布）

> **这份文件什么时候读**：第一次装这个插件、想知道面板在哪、装完「什么都没发生」、或者以后要发 npm 时。
> 它是插件主文档 [`README.md`](../README.md) 的参考文件 —— README 只留入口、速查与导航。
>
> ⚠️ 一句话：**本包已发布到 npm**（`dsh plugin --profile web add dsh-miliastra@0.3.0`，见 §2 方式一）；
> 要**改插件本身**才走**源码 / git**（软链 + 注册 bundles + 重启 GUI）。

---

## 1. 最短路径：先跑通一次

装好之后（§2），**第一次上手只要三步**：

| 第几步 | 调什么 | 你会拿到什么 |
|---|---|---|
| **① 定位** | `miliastra_health {}` | 当前正在开发的关卡 / 活文件绝对路径 / 地图 `.gil` / 日志目录 |
| **② 读或写代码** | `miliastra_code {"op":"inspect"}` 先体检 → `miliastra_code {"op":"deploy","source":"<本地 .lua 绝对路径>"}` 投进沙箱 | 体检报告 / 部署结果（**先备份 → 二进制拷贝 → 比对 SHA-256 → 校验无 BOM**） |
| **③ 验证** | `miliastra_playtest {"op":"status"}` → **请人点试玩** → `miliastra_log {"op":"tail","tag":"<脚本里打的 TAG>"}` | 是否在试玩；脚本 `print` 出来的运行时正文 |

三条必须记住的：

1. **路径不写死** —— 换账号、换图、重建关卡都会换目录，一律从 `miliastra_health` 拿。
2. **写操作只在 `miliastra_code` / `miliastra_probe` / `miliastra_sim`**：前两个自带备份与双钥匙，
   `miliastra_sim` 只写插件数据目录下的 `simulator/` 与 `shots/`（**不碰游戏存档、地图与活文件**），其余工具一个字节都不写。
3. **试玩按钮只能人点** —— 没有自动化通道，也不做破解。插件只负责把人点完之后的开跑 / 结束接住。

## 2. 安装（方式一 npm / 方式二 源码）

### 2.1 两种方式与区别

**npm 已可装**（0.3.0 起）：`dsh plugin --profile web add dsh-miliastra@0.3.0` → 重启 `dsh web`。
> 上面这条是**方式一**；要**改插件本身**（或想跟源码目录联动）才需要下面的**方式二**：

- **npm 方式**（推荐，日常用）：`dsh plugin --profile web add dsh-miliastra@0.3.0` → 重启 `dsh web`。插件声明了 `dsh.bundle.patch`，装完会自动写进 `dsh.profile.bundles`；
- **源码方式**（要改插件本身时用）：把仓库克隆下来、软链进 profile、再注册进 bundles（下面是完整步骤）。⚠️ **只放软链不注册 bundles，插件完全不会加载。**

> 发布新版本到 npm 的完整流程（含发布前确认清单与三条不可逆的注意点）→ 见 §7。

### 2.2 源码方式：三步装好（完整命令）

```powershell
# ① 克隆
git clone <本仓库地址> dsh-miliastra
cd dsh-miliastra

# ② 软链到 web profile 的 node_modules（开发态）
cmd /c mklink /J "$env:USERPROFILE\.dsh\profiles\web\node_modules\dsh-miliastra" (Get-Location).Path

# ③ **注册进 bundles** —— 少了这步插件完全不会加载
#    编辑 %USERPROFILE%\.dsh\profiles\web\package.json，把 "dsh-miliastra" 加进 dsh.profile.bundles：
#      { "dsh": { "profile": { "bundles": [ "...", "dsh-miliastra" ] } } }

# ④ 重启 Web GUI
dsh web
```

`dsh.profile.bundles` 里那一行**不是可选的**：

> ⚠️ **只放软链不会让插件被装配**：启动期不扫描 `node_modules`，装配来源只有 profile 的
> `dsh.profile.bundles`（或 profile `cordis.patch.yml` 里显式 insert 一行）。
> 这条错了的表现是**完全静默**：文件都在、什么也没发生。

### 2.3 软链是「自用 / 开发」方式，不是交付方式

本机 pnpm 是 `nodeLinker: hoisted`，手搓的软链**不在 profile 的 `dependencies` 里**：

> ⚠️ 下一次 `dsh plugin add/install` 会**把它清掉**。所以要长期留着，就别在那个 profile 上跑装插件；
> 或者改用 profile `cordis.patch.yml` 里显式 insert。

### 2.4 装完怎么自查（4 个信号，都不用猜）

| # | 怎么查 | 期望看到 |
|---|---|---|
| ① | `curl http://127.0.0.1:3080/miliastra/status` | 有 JSON 返回（`ok:true`）。**404 = Host 半边没加载**（bundles 没写 / 没重启） |
| ② | 同一个 JSON 里的 `clientHalf` | `declared:true` + **`inBootGraph:true`** —— 这一行为 true，浏览器才会加载面板 |
| ③ | 调 `miliastra_echo {"text":"ping"}` | 原样回显 + 插件版本（**怀疑插件没生效 / 参数丢了时先调它**） |
| ④ | 刷新页面看**侧边栏底部** | 出现「千星奇域」徽章（在「设置」旁），点开是三栏面板 |

`clientHalf.rev` 是 client bundle 内容的**哈希**：改完 `lib/client.js` 再查 `/status`，这个值会变 ——
所以「刷新页面能不能拿到新版」有机器凭据。

> 只有 ①②③ 通过、④ 看不到徽章时，看浏览器控制台的 `[dsh-miliastra]` 日志（client 半边默认全静默，
> 这几行日志是故意留的）——逐条对照见 [`配置与开发.md`](配置与开发.md) §「客户端排障」。

### 2.5 卸载 / 回退

```powershell
# ① 从 %USERPROFILE%\.dsh\profiles\web\package.json 的 dsh.profile.bundles 里去掉 "dsh-miliastra"
# ② 删掉软链 —— **junction 要用 rmdir**，别用 Remove-Item/rm -rf（那会顺着链接删掉仓库真身！）
cmd /c rmdir "$env:USERPROFILE\.dsh\profiles\web\node_modules\dsh-miliastra"
# ③ 重启 dsh web
```

## 3. 面板在哪、里面有什么

- **位置**：注册在官方槽位 `sidebar.footer.action` —— **侧边栏底部**（「设置」旁），入口徽章写着「千星奇域」。
- **形态**：点开是一个**三栏状态浮层**（粉蓝主调），头部固定、三栏各自独立滚动。

| 栏 | 内容（要点） |
|---|---|
| **① 关卡** | 关卡切换（默认**自动跟随**换图，点某一关即手动锁定）；进程是否在跑（编辑器 / 游戏）；地图体检（名称版本 / 客户端控件条数 / 可创建模板胶囊 / 模板区为空的告警） |
| **② 代码** | 活文件选择器（一个关卡可能有多个 `.lua`，所有操作跟着它走）；活文件体检（大小·行数 / SHA-256 / **BOM** / 编码）；脚本一致性（地图快照 vs 本地活文件）；备份清单与逐条还原；部署 |
| **③ 日志与画面** | 历史局面胶囊（点某一局只看那一局）/ TAG 汇总与过滤 / 日志正文；截图目录·张数·占用、截游戏 / 截编辑器 / 清理（两步确认）；**高级诊断**（默认收起）：读界面控件（只读）+ 探针（**会临时覆盖活文件**） |

另有**浏览器试玩页** `GET /miliastra/play`（PixiJS WebGL，与面板内嵌的 `iframe` 是同一个会话）——
它是**给人玩的**，但玩完**不关会话就能让 AI 接手**（`miliastra_sim op=verify fromHistory:true` 把那一局变成回归用例）。

面板的完整细节（自动跟随怎么判、多活文件怎么切、一键还原的语义）→ [`面板与活文件安全.md`](面板与活文件安全.md)。

## 4. 生效边界（改什么要重启，实测）

| 改了什么 | 怎么生效 |
|---|---|
| `index.js` / `lib/*.mjs`（**Host 半边**：工具、路由、系统提示段） | **必须重启 `dsh web`**。实测：`cordis.patch.yml` 触发的 `patchReload: live` 重载**不会**重新 import Host 模块 |
| `lib/client.js`（**Client 半边**：面板） | 刷新浏览器即可（client bundle 在激活时被读进内存） |
| `package.json` / `exports` / `dsh.profile.bundles` | 重启（bundle 列表在启动时快照） |

> 本仓库**不写死任何绝对路径**：存档根目录从 `os.homedir()` 推出来，可用 `MILIASTRA_LOCALLOW` 覆盖；
> 截图 / 模拟器工作区在插件数据目录（`MILIASTRA_DATA_DIR` 可整体覆盖），备份目录用 `MILIASTRA_BACKUP_DIR`。

## 5. 常见坑（按症状查）

| 症状 | 多半是什么 | 怎么办 |
|---|---|---|
| **装完什么都没发生**（没有徽章、AI 也看不到工具） | 只放了软链，没写进 `dsh.profile.bundles` | §2.2 第 ③ 步；再重启 `dsh web` |
| `curl …/miliastra/status` **404** | Host 半边没加载（bundles 没写或没重启） | 同上；注意改 Host 后**必须重启**（§4） |
| 改了 `lib/client.js` 但面板没变 | 浏览器没刷新 / 拿到的是旧 bundle | 刷新页面；用 `/status` 的 `clientHalf.rev` 核对是否变了 |
| 面板 / 工具重装了又消失 | `dsh plugin add/install` 把 hoisted profile 里的手搓软链清掉了 | §2.3；重做软链 |
| **试玩了却没有日志** | ① 压根没从编辑器开试玩（游戏客户端开着 ≠ 在试玩）；② 编辑器「日志」面板里 `客户端脚本` 没勾 | 先用 `miliastra_playtest {"op":"status"}` 看**现在到底在不在试玩**（它读 `output_log.txt`，0.07~0.18 秒延迟） |
| 判断「开跑那一刻」时 `.gia` 里什么都没有 | `.gia` **不是实时的**：一局结束后才落盘 | 用 `miliastra_playtest op=wait`（唯一能看到开跑的通道）；要截图用 `miliastra_shot op=burst awaitPlaytest:true` **一次调用**搞定 |
| 部署完试玩，脚本像没生效 | 改了本地文件但没 push / 或部署发生在**正在进行的试玩**中途 | 部署**不会热加载正在进行的试玩**：stop → deploy → start；且改完文件至少等 2~3 秒再试玩 |
| 游戏打印 `Read text file with BOM header may cause Lua error` | 活文件带了 UTF-8 BOM | `miliastra_code {"op":"fixbom"}`（只去掉那 3 个字节，其余不动） |
| 探针跑完，玩法脚本不见了 | 探针会**临时覆盖活文件**（这是设计，为了问游戏一句话） | 用 `miliastra_code {"op":"restore"}` 还原（不传 `backup` 就用固定名那份） |
| AI 说「已改好」，但地图没变 | AI 只能改文件层；**建模板 / 挂脚本 / 点试玩没有自动化通道** | 认边界：见 [`关键知识与能力边界.md`](关键知识与能力边界.md) |
| 想离线先跑一遍逻辑 | —— | 用内置模拟器（`miliastra_sim`）：**模拟器通过 ≠ 真机通过**，真机那一步仍要人点试玩 → [`模拟器与视图.md`](模拟器与视图.md) |

## 6. 什么时候该换一条路（别硬刚）

| 你想做的事 | 走哪条 |
|---|---|
| 只想读日志 / 看画面 / 确认在不在试玩 | 工具（`miliastra_log` / `miliastra_shot` / `miliastra_playtest`），**不用开模拟器** |
| 想在游戏之外搭界面、改控件、跑 `levelScript`、出 PNG | `miliastra_sim`（真机工程用 `op=bind` 搬进来） |
| 需要运行时真相（某个控件能不能建、某个枚举叫什么） | `miliastra_probe`（部署 → **人重新试玩一局** → collect → **记得 restore**） |
| 要人肉判断的（观感、手感、真机联机） | 只有人 —— 工具只给数字，不下判决 |

## 7. 发 npm（**0.3.0 起已发**）

> 包页：<https://www.npmjs.com/package/dsh-miliastra>。这一节是**发版流程**（含实测过的坑），下次发新版本照它走。
> 判据：`private` 必须不存在/false；`prepublishOnly` 会自动跑「构建产物比对 + npm test」，不过就发不出去。

```powershell
npm login                                   # 浏览器 / 2FA；没账号先到 npmjs.com 注册并验证邮箱
npm publish --dry-run                       # 先看会发什么（不真发）
npm publish                                 # 真发；开了 2FA 时加 --otp=123456
npm view dsh-miliastra version              # 验证：打印版本号即成功
```

发布之后，别人才可能用一条命令装（**声明了 `dsh.bundle.patch` 会自动写进 `dsh.profile.bundles`**）：

```powershell
dsh plugin --profile web add dsh-miliastra@0.3.0
dsh web
```

**发布前请确认：**

- `private` **必须是 false 或不存在** —— 写了 `"private": true` 时 npm 会直接拒绝
- `files` 是**白名单**：没列进去的文件不会进包（`CHANGELOG.md` 就是后补进去的）
- `license` 与仓库里的 `LICENSE` 一致
- `repository` / `homepage` / `bugs` 指向真实地址
- registry 指向**官方源**（`npm config get registry` 应是 `https://registry.npmjs.org/`；指向淘宝等镜像时发布必失败）
- `prepublishOnly` 会自动跑测试 —— 本项目配置为 `npm test`（先跑 `node tools/lint.mjs`，再跑全套测试，不过就发不出去）

**三条不可逆的注意点：**

1. **同名同版本不能重发** —— 改完要 `npm version patch`（→ `0.2.1`）再发
2. **72 小时内**可以 `npm unpublish`，超过就再也撤不回来了
3. 包名是**全局唯一**的，先占先得
