### 试玩开跑侦测（`miliastra_playtest`）

**先说一件事：`.gia` 不是实时的。**

本机 22 个 `.gia` **全部** `CreationTime == LastWriteTime`，而且都**晚于文件名时刻**：

| 文件 | 名字时刻 | **落盘时刻** | 该局结束（`QuickSwitch`） |
|---|---|---|---|
| `…21-46-05_157` | 21:46:05 | **21:47:07** | 21:46:58 |
| `…21-29-40_156` | 21:29:40 | **21:31:40** | 21:31:33 |
| `…21-24-16_155` | 21:24:16 | **21:26:14** | 21:26:06 |

**局在跑的时候，磁盘上根本没有这个文件。**所以「盯 `.gia`」只能等这一局结束 ——
想知道「开跑那一刻」必须换通道。

游戏客户端自己会写一份 Unity 日志 `%USERPROFILE%\AppData\LocalLow\miHoYo\<品牌>\output_log.txt`，
**每行带毫秒时间戳、持续追加**，里面有两行平台级标记：

```
[2026-09-23 21:46:02.419] Genshin Loading Log: OnReceivePlayerEnterSceneNotify 1037586 - NowTimeStamp:1790171162
[2026-09-23 21:46:02.420] Genshin Loading Log: BeyondLevelPlayModule SetCurLevelData ... isTrial:True   ← 开跑
[2026-09-23 21:46:58.960] Genshin Loading Log: StartQuickSwitchSceneAction ... QuickSwitchToBeyondSettleSceneNormally   ← 结束
```

**实测延迟**（Δ = 我们读到它的时刻 − 它自己写的时刻）：

| 事件 | 日志自己写的 | 我们读到的 | Δ |
|---|---|---|---|
| 开跑 | 21:46:02.420 | 21:46:02.600 | **+0.18 秒** |
| 结束 | 21:46:58.960 | 21:46:59.033 | **+0.07 秒** |

三条附带事实：

- 它是**平台级**的：脚本一行都不 `print`、磁盘上没有 `.gia` 的局（本机 20:36 / 21:11 那两局），它照样记；
- 它带的 `NowTimeStamp:<epoch 秒>` **等于**那一局 `.gia` 里 `instance` 的第三段
  （`47504-<账号>-<这个>-<毫秒>`）→ **实时开跑与事后日志能对号**；
- 这份日志**按游戏启动换代**（游戏重启会重建），所以 offset 要处理回退。

**两种用法：**

```
# ① 问现状
miliastra_playtest op=status
# → inPlaytest / startedAt / elapsedSec / epochSec / recentRuns（最近 8 局的起止与时长）

# ② 等下一次开跑；命中后接着截图 = 「开跑约 3 秒后的画面」
miliastra_playtest op=wait afterSec=3
miliastra_shot op=capture target=game
```

`op=wait` 的参数：`timeoutSec`（默认 90，上限 300）、`backSec`（回扫刚过去那一局 ——
人点了试玩再叫 AI 时用得上）、`afterSec`（命中后再等 N 秒）、`pollMs`。
**超时不报错**，如实回 `hit:false` + `timedOut:true`。

> ★ 0.3.1 补了两件事，都在本节下面的链接里：
> **`op=status` 的 `localGia`**（本局 `.gia` 到底落盘了没有 —— 没有它就会把上一局的日志当成本局证据）
> 与 **`op=arm`**（一次调用完成「等开跑 → 按秒点抓拍 → 落盘」，人点完试玩 AI 不用再参与）。

面板 ③ 栏顶部有「**试玩开跑**」卡片：状态、本局编号、最近几局、信号来源与实测延迟，
以及「**开跑自动截图：开/关**」+ 3/5/10 秒 —— **默认关**（磁盘是用户的，没人点过就不该自己往里写图片）。

> ⚠️ 别用 `.gia` 记录里的 `level2` 字段当「局内秒表」：实测 151 那局 25 条全是 1、
> 155 第 1 局从 34 起、`90003` 那一路能到 842 —— 语义仍 `unknown`。
> 要时间轴只认日志行自己的毫秒时间戳。

## 截图（`miliastra_shot`）

运行时日志能回答「**代码跑了没、print 了什么**」，回答不了「**画面对不对**」——
控件到底挂上去了没、位置歪没歪、颜色对不对。这一环以前只能靠人截图再手动贴回来。

```
miliastra_shot op=capture target=game label=试玩第1局   # 默认就是 capture + game
miliastra_shot op=list                                 # 截到哪去了、多少张、占多大
miliastra_shot op=clean keepLast=5 olderThanDays=7      # 先看将删哪些（默认 dryRun）
miliastra_shot op=clean all=true dryRun=false confirm=true   # 真删（双钥匙）
```

**图片存在插件自己的数据目录**：`~/.dsh/miliastra/shots\`（`MILIASTRA_DATA_DIR` 可整体覆盖）。
**故意不放两个地方**：

| 不放哪 | 为什么 |
|---|---|
| 游戏存档目录（`external_lua_file\`） | 那是米哈游的地盘。混进一堆 PNG 会污染存档目录，而「活文件 = 那个目录里的 `.lua`」这类判断最怕旁边多东西 |
| 本插件的包目录（`node_modules\dsh-miliastra\`） | **插件升级 / 重装会整个替换掉那个目录，用户的图会凭空消失** |

**绝不自动删。** 删除不可恢复，所以：

- `op=clean` 必须显式给条件（`all` 或 `olderThanDays`）；**什么都不给就一张都不删**并说明原因
- `keepLast` 是保护网，**任何模式下都生效**（哪怕 `all:true` 也至少留最新 N 张）
- 真删要 **`dryRun:false` + `confirm:true` 双钥匙**
- 面板上同样是**两步**：点「清理…」先看将删清单，确认按钮才出现

**回执恒带窗口身份**：`process` / `pid` / `title` / `mode` / `blackRatio`。不是装饰 ——
这个功能的第一版抓回来的其实是**恰好压在前面的浏览器**，而回执只有 `{ok:true,path}`，
**光看返回值完全无法发现**，是靠人眼看 PNG 才暴露的。现在改成：

| 字段 | 含义 |
|---|---|
| `mode: "printwindow"` | 让窗口自己渲染（`PrintWindow` + `PW_RENDERFULLCONTENT`）。**不需要窗口在前台**，被遮挡也行 |
| `mode: "screen"` | 退回屏幕抓取。**只有目标窗口真在前台才对** → 此时 `front:false` 会被标成 `suspect:true` |
| `blackRatio` | 量出来的黑像素占比。> 98.5% 判 `suspect`（Unity/D3D 的 swap chain 偶尔让 PrintWindow 返回全黑） |
| `uniformRatio` | **单一颜色**占比。> 98.5% 判 `suspect` —— 因为**全白的空图能通过「全黑」检查**，必须单独量这一项 |
| `pid` / `title` / `candidates` | 明确告诉你**截到的是哪个窗口**，以及它是在哪几个候选之间挑出来的 |
| `suspect` / `warning` | 上面任何一条不过关就置位，并给出原因。**别忽略它**：`ok:true` 不代表这张图有用 |

## 一个进程有多个窗口 —— 选窗规则（踩过两次）

**进程不等于一个窗口。** 本机实测 `BeyondEditor.exe` 同时有 **900×800 的日志窗**和
**160×28 的最小化残片**，而 `Process.MainWindowHandle` 指向了后者 ——
于是「截编辑器」返回了一张 **160×28 的菜单栏碎片**，回执照样是 `ok:true`。

现在的规则：

1. **枚举该进程的每一个可见顶层窗口**，按**面积从大到小**取第一个（同等大小优先没最小化的）；
2. 最大的那个仍小于 **200×150** → **直接拒绝**（报错并列出所有候选），
   因为这么小的图永远不是想要的，写进截图目录只会变成要清理的垃圾；
3. 想指定就用 `window=<标题子串>`（例如 `window=日志`）；
4. 回执里带 `candidates[]`（每个候选的 `title / w / h / area / minimized`），选窗依据**看得见**。

## 缩略图预览

面板里看得到缩略图，但**页面不会去拉原图**：一张原图 2.4 MB，列十几张就是 30 MB。
所以 Host 在**截图时顺手生成一张 ~320px 的预览**（同一个 bitmap，不额外起进程），
面板只加载预览、`loading="lazy"`，点开才在新标签页看原图。

- 预览放在 `<shots>\_thumbs\`，**同名**；`listShots` 只收顶层文件，所以预览不会被当成截图
- `miliastra_shot op=clean` 删截图时会**连预览一起删**（否则 `_thumbs` 会攒一堆孤儿）
- 面板上的图走 `GET /miliastra/shot?name=<文件名>[&thumb=1]` —— 这是插件里**唯一**返回非 JSON 的路由，
  所以守卫写死在那里：只允许截图目录内的 `.png`，`name` 不许带路径分隔符（`../`、绝对路径、子目录一律 400）

> ⚠️ 截图在 Windows 上由 `lib/capture-window.ps1` 完成（Node 没有内建窗口截图能力）。
> 那个脚本**刻意保持纯 ASCII**：PowerShell 5.1 在 `.ps1` 没有 BOM 时按 ANSI 解码，任何中文都会变乱码。
> 它还把所有非 ASCII 输出转义成 `\uXXXX` —— 因为 PS 5.1 重定向 stdout 用的是**控制台代码页**（本机 936/GBK），
> 不是 UTF-8，窗口标题「原神」会以 GBK 字节到达 Node 变成 `ԭ��`。

## 连拍（`miliastra_shot op=burst`）

想让工具自己等开跑、再连拍，**一次调用就够**：

```jsonc
{ "op": "burst" }                                            // ① 立刻 5 张
{ "op": "burst", "awaitPlaytest": true, "afterSec": 3 }       // ② 等开跑 → 等 3 秒 → 5 张
{ "op": "burst", "count": 8, "dryRun": true }                 // ③ 先看计划（一张都不拍）
```

为什么不是「先 `playtest op=wait` 再逐个 `capture`」：两次调用之间的往返延迟（1~3 秒）
会直接毁掉时间精度，而连拍的全部意义就在时间上。判据与 `miliastra_playtest op=wait`
**共用同一份实现**。

> ⚠️ **`burstMs` 不是「每 N 毫秒一张」**，它只是**两张之间的额外等待**。
> 单张自身还要 **~2.6 秒**（本机实测：起 PowerShell + `PrintWindow` + 顺带出缩略图），
> 所以 `burstMs=800` 的真实帧距是 **~2600ms**。回执里恒定给 **`measuredIntervalMs`**，并在
> 差距大时明说「差额是单张自身耗时，不是没生效」。
>
> **推论（重要）**：单帧寿命 **<1 秒**的特效，这个速度**注定只能抓到 1~2 帧** ——
> 是引擎/进程启动的地板。要看快特效得改脚本（把过程画在控件上，或分多局抓）。

真机证据（一次性）：`count=3` → 3 张全成、无 suspect、`span=5201ms`、`measuredIntervalMs=2600`，
每张 1456×939 / 2.4 MB。**某一张失败就停手**（不白耗剩下的时间），回执给 `abortedAt`。

> 回执**不带图片二进制**，只给 `GET /miliastra/shot?name=<file>`（原图）与 `&thumb=1`（小图）。
> **截图不会自动删**，记得 `op=clean` 看一眼。

### 短局的时序：`startAfterSec` / `untilGone` / 逐张 `inRun`（0.3.1，反馈 C1）

**实测事故（2026-09-25）**：一局只有 **16 秒**（`startedAt 16:34:21.804` / `endedAt 16:34:37.521`），
而「命中后留 **8 秒**加载窗口再连拍 4 张」（每张 2.6~3.5 秒）⇒ **4 张全部落在局外**（拍于 16:34:38~16:34:49），
可回执里只有一串 `elapsedMs`，**得自己算**才知道一张都没用。

| 旋钮 | 作用 |
|---|---|
| `startAfterSec` | 命中开跑后**等 N 秒立刻开拍**（**这才是「我想从开局第 N 秒开始拍」那个旋钮**；不传 = 沿用 `afterSec`，老调用行为一个字不改） |
| `untilGone` | **拍到这一局结束就自动停**（判据与 `playtest` 同一份，只吃基线之后新增的日志行）；停了回 `stoppedBecause:"run-ended"`，剩余张数不再耗 |
| `frames[].inRun` | **这张是不是在本局窗口内**拍的（`true`/`false`/`null`）；回执另有 `inRunCount` / `outsideCount` / `runWindow` |

```jsonc
// 短局（< 20 秒）该这么拍：命中就拍、局结束就停，逐张告诉你在不在局内
{ "op":"burst", "awaitPlaytest":true, "startAfterSec":1, "untilGone":true, "count":20, "label":"短局" }
```

> ⚠️ `backSec` 回扫命中的局**可能已经结束**（D1 踩过：「拍到的是局外画面」）：这时回执里的
> `runWindow` 直接带 `endedAtMs`、每张都标 `inRun:false`，并附一句 `warning` —— 不用再自己去对时间。
>
> **C2 不退化**：`measuredIntervalMs` / `spanMs` / `clamped` 一个字没改（`feedback3-test` 有断言钉住）。

### 「武装后台截图」：`miliastra_playtest op=arm`（0.3.1，反馈 D1）

一次调用完成**「等新局开跑 → 按给定秒点抓拍 → 落盘 → 回执」**，人点完「试玩」之后 AI 不用再参与：

```jsonc
{ "op":"arm", "afterSec":[8,12,16,20], "timeoutSec":300 }
```

- 等的是**下一次**开跑（默认**不回扫** —— `backSec` 会命中已经结束的旧局，那正是要消灭的坑之一）；
- 每个秒点**只拍一张**（不是连拍），相对**开跑时刻**算；
- **这一局一结束就停**：剩下的秒点如实标 `{skipped:true, reason:"run-ended"}`，不白耗；
- 回执：逐张 `{afterSec, file, atMs, elapsedMs, inRun, ok, suspect}` + `startedAt/startedAtMs/endedAtMs/durationSec`
  + `inRunCount` / `skippedCount` + `localGia`（本局 `.gia` 落没落盘）；
- 命中时那一局**已经结束**（`backSec` 回扫）→ `endedBeforeFirstShot:true`，**一张都不拍**并说明为什么。

## 防「静默丢代码」：部署指纹 / `fixbom` / `ErrorLog` / 部署后对账

这四件事都是**静默失败**的解药 —— 出问题时**没有任何报错**，只是你看到的和以为的不一样。

### ① 部署指纹：活文件被写回旧版（`.miliastra-deploy.<脚本名>.json`）

实测**编辑器保存时会把脚本面板里的内存版写回活文件**（那次保存让 `.gil` 从 54.5KB 涨到 65.9KB，
差值 ≈ 那次部署的脚本增量）。也就是说**部署成功 ≠ 编辑器拿的是新版** ——
而以前这种情况**没有任何迹象**。

所以 `op=deploy` 成功后会在备份目录写一份指纹，之后 `op=inspect` 每次比对：

```
miliastra_code op=inspect
→ deploy: { hasFingerprint:true, sameAsDeploy:false, changedSinceDeploy:true,
            bytesDelta:-412, lineDelta:-9,
            note:"活文件与上次部署**不一致** —— 多半是编辑器把脚本面板里的内存版存回了磁盘…" }
```

没有指纹时**如实说没有**（`hasFingerprint:false`），不假装一致。写指纹失败**不影响部署成败**。

⚠️ **指纹按活文件名索引**（2026-09-25 修）：一个关卡可以有**多个活文件**（不同角色 / 模块各挂一个脚本），
而指纹原来在备份目录里**只有一份** —— 多活文件目录下必然串：实测拿 `测试.lua` 的指纹去比刚部署的
`背景图片.lua`，得到假告警「活文件与上次部署不一致（多半是编辑器存的）」。现在落 **两份**：

| 文件 | 用途 |
|---|---|
| `.miliastra-deploy.<脚本名>.json` | 这次真正写、**`op=inspect` 优先读**的那份（按活文件名索引） |
| `.miliastra-deploy.json` | 旧版单份（照写，**兼容**老回执 / 老版本留下的记录；只在按名取不到时兜底读） |

回退到旧版单份、而那份**属于另一份活文件**时：回执带 `deploy.fingerprintBelongsTo`（它属于谁）+
`deploy.foreignFingerprint:true`，并且 **`changedSinceDeploy` / `sameAsDeploy` 都是 `null`** ——
两个不同文件的哈希本来就不同源，判「变了 / 没变」都是假结论。`op=deploy` 回执里
`deployFingerprint.path` 仍是旧版单份（兼容既有调用方），`pathByName` 才是这次写进去、之后会被读的那份。

### ② `op=fixbom`：活文件带 BOM 时只去那 3 个字节

BOM **不是本工具加的**（部署路径会拒绝带 BOM 的源文件）—— 实测它来自**新建关卡时编辑器自己写的活文件**：
本机备份里确实有一份 `EF BB BF` 开头的 **22449** 字节版，同一份内容无 BOM 是 **22446** 字节，**正好差 3 字节**
（原神实测打印 `Read text file with BOM header may cause Lua error`）。

| 情况 | 行为 |
|---|---|
| 本来就没有 BOM | **什么都不做**（连 mtime 都不碰） |
| 备份失败 | **立即中止**，一个字节都不动 |
| 正常 | 备份 → 原子写 → 校验（**逐字节比对：除了那 3 字节其它必须完全相同** + 无 BOM + 仍是合法 UTF-8） |
| 校验不过 | **自动回滚**回带 BOM 的那一版 |

⚠️ 回执里会**提前写明副作用**：`<原名>.bak` 这时指向「带 BOM 的那一版」，
而 `op=restore` 会**故意拒绝**还原它（那种文件还原回去 Lua 照样报错）。

### ③ `ErrorLog.txt` 巡检

官方文档：**循环调用 / 挂载失败这类错不进 `.gia`**，只在客户端脚本同目录写 `ErrorLog.txt`。
所以「`.gia` 里干干净净」**不能**单独当成「脚本没出事」的证据。
`miliastra_health` 与 `op=inspect` 都会顺手扫：有 → 报大小 / 行数 / 首几行；**没有也如实显示「没有」**。

### ④ 部署后自动对账 + 「这份挂过没有」

部署完立刻用 `.gil` 里嵌的脚本快照与刚投进去的活文件比 SHA，结论直接写进回执的 `nextStep`：
「可以试玩了」还是「**先在编辑器里存盘**」；对不了账（没有 `.gil` / 地图里没有脚本映射）时**如实说**，
且 `nextStep` 里**不会**出现「可以试玩了」。

★ **`nextStep` 还要分清「这份挂过没有」**（2026-09-25 同事实测）：对**从没在编辑器里挂载过的新脚本**，
「先存盘」解决不了任何问题（地图里根本没有这条挂载记录），真正缺的是「**先挂到容器节点上**」。
判据在回执的 `mount` 里（纯函数 `mountStatusOf`，与「当前活文件是谁」用的是同一套名字比较 —— 忽略目录与 `.lua` 后缀）：

| `mount` | 含义 | `nextStep` |
|---|---|---|
| `mounted:true` | 地图里嵌的脚本名与这份对得上 | 原来的「存盘 / 重新试玩」 |
| `mounted:false` | 对不上（挂的是**别的**脚本） | 「这份**还没挂到容器节点上** → 先在编辑器里挂到客户端控件容器的容器节点上，再试玩」 |
| `known:false` | 拿不到脚本映射记录（没 `.gil` / 没存盘） | **明说「挂没挂过判断不了」**，再说原来那句（不编结论） |

⚠️ **跨脚本不比**（2026-09-25 修）：地图里嵌的如果是**另一个脚本**（GIL 的 `name/file` 与本次活文件名对不上），
回执给 `reconcile.skipped`（点名「地图快照属于另一个脚本（X），本次比的是 Y；先确认哪个才是你正在改的」）、
`match` 为 **null**，并且 **`nextStep` 里不再出现「先别急着试玩」** —— 那是拿两个不同脚本的哈希比出来的假告警。
`miliastra_map op=script` 同一条判据（名字对不上时 `skipped`，不再给「不一致」的结论）。

## 「本局的 `.gia` 到底有没有」—— 取证链上最容易张冠李戴的一环（0.3.1，反馈 A2）

**实测事故（2026-09-25，关卡 `1073741835`《侦探_多组件》）**：16:23 / 16:26 / 16:29 / 16:34 四局**结束后都没有生成 `.gia`**
（日志目录最新仍是 `2026-09-25_16-16-23_184`，属 16:16 那局）。这时 `miliastra_log op=grep|runs` 会**静默回退到旧文件** ——
`file` 字段虽然标了文件名，但很容易被当成「本局日志」（子代理三次抓取都踩了同一个坑）。

现在有两道判据，**都走同一份事实**（`.gia` 里 instance 第三段 = 那一局的开跑时刻，与 `miliastra_playtest` 报的 `epochSec` 同源）：

| 入口 | 新增字段 | 说明 |
|---|---|---|
| `miliastra_playtest op=status` | `localGia.status` / `landed` / `file` / `note` | `running`（本局还在跑）/ `landed`（**已落盘**）/ `missing`（**未落盘**，可能该局不产生）/ `none`（目录里一个都没有）/ `unknown`（判断不了） |
| `miliastra_log op=tail\|grep\|runs\|tags\|metrics` | `staleLog` / `logBelongsTo` / `staleLogWarning` | `staleLog:true` = **这份日志不属于本次会话**；`logBelongsTo` 形如 `2026-09-25_16-16-23_184_201170108.gia (epochSec 1790324179)` |

判据是**有没有本局那个 epochSec**，不是比 `mtime` —— `mtime` 分不清「本局」与「更晚的另一局」。

### 顺带查清：为什么有些局不落 `.gia`

**已查明的部分（有文件层证据）**：

- `.gia` 里**只装客户端脚本自己 `print` 出来的记录**。实测两份文件（`…15-38-45_168` 70 条 / `…16-16-23_184` 131 条）
  **全部**是 `[侦探1/*]` 前缀的脚本输出，`channel` 字段是关卡名，`time` 字段是**关卡加载时刻**而不是记录时刻。
- 文件名里的时间戳 ≈ **关卡加载完成**那一刻（实测 `SetCurLevelData` 16:16:19.872 → 文件名 `16-16-23`），
  所以「文件名时间早于你那一局」并不代表它是旧局，要看 `instance` 里的 `epochSec`。
- ⇒ **一局如果脚本一条 `print` 都没有，磁盘上就不会出现这一局的 `.gia`**（文件是按需创建的）。

**未查明的部分（如实写「未查明」）**：

16:23 之后连续 6 局都没有 `.gia`，而**同一时间窗**里：

- `output_log.txt` 中这些局都有正常的开跑/结束标记（`SetCurLevelData … isTrial:True` / `QuickSwitchToBeyondSettleSceneNormally`），
  **没有任何 Lua 报错**；
- `BeyondLocal` 下**不存在** `ErrorLog.txt`（官方口径：循环调用 / 挂载失败这类错只写它）；
- 16:16:52 之后本机**没有**任何编辑器侧配置文件被改写（扫过 `BeyondLocal` 全量文件 mtime）。

所以**无法从文件层区分**下面两种原因（两者表现完全一样：没有文件）：

1. 那几局脚本确实一条 `print` 都没打（脚本没跑到 `OnStart` / 编译失败静默）；
2. 编辑器「日志」面板里的 **`客户端脚本`** 没勾上（或日志面板被关掉），输出根本没进 `.gia`。

**复测口径（成本最低）**：跑一局 → `miliastra_playtest op=status` 看 `localGia`；
若为 `missing` 而脚本里明明有 `print`，先回去确认「日志 → 客户端脚本」勾上了，再跑一局对比。

## 多脚本工程：脚本映射表与「已挂载集合」（0.3.1，反馈 A1）

**实测事故（2026-09-25，关卡 `1073741835`《侦探_多组件》，6 个客户端脚本）**：
6 个脚本**确实挂在容器上**，但 6 次 `op=deploy` 回执全部 `mount.mounted:false`，还提示「还没挂到容器节点上」。
根因：`mountedScriptNames()` 只读 `gil.script`（`#50` 的**第一条**），而多脚本地图的 `#50` 是

```
#50 { #1「新建客户端脚本」(旧占位) ; #1「主控 main」 ; #1「表现 view」 ; … }    ← 共 7 条
```

第一条恰好是旧占位 ⇒ 拿「新建客户端脚本」去比本次的 `主控 main.lua`，**永远对不上**。

### `.gil` 里的两块事实（都用结构判，不靠扫字节）

| 事实 | 字段形状 | 谁读它 |
|---|---|---|
| **脚本映射表**（有哪些脚本） | `#50 → #1 ×N { #1 映射索引, #2 脚本名, #3 文件名, #5 源码全文 }` | `readScriptMappings()` |
| **挂载引用**（谁挂了谁） | 任意层级的 `#5 { #1 槽位号, #2 脚本映射索引 }`；`#2` 落在映射表里才算 | `readScriptMounts()` |

`mountedOn` = 「离这条 `#5` 最近的那层 `#1` 字符串」—— 实测六脚本那一组全挂在 **`侦探1-7`**，
旧占位挂在 `未分类页签`。⚠️ **别用「映射索引在文件里出现几次」代替它**：那分不清资源记录的自引用与控件的挂载引用。

### 判定口径（`mount`）

- `mountedNames` **优先**取**已挂载集合**里的脚本名（`mount.source = "gil-script-mounts"`）；
- 存档里读不到挂载信息（老图没有 `#6` 界面控件组层级）→ **兜底**用全部映射名（`gil-script-names`），
  至少不再是「只拿第一条占位名」那种假阴性；
- 整个映射表都取不到 → `known:false`，如实说「判断不了」，**绝不瞎报 false**；
- 已挂载集合**确定为空** → `known:true, mounted:false`（这是一句结论，不是「判断不了」）。

### `miliastra_map op=script` 变成多脚本口径

```jsonc
{ "mappings":[ {"mappingId":1073741827,"name":"主控 main","file":"主控 main.lua",
                "bytes":4367,"sha256":"…","mounted":true,"mountedOn":"侦探1-7"}, … ],
  "embedded":{ "mappingId":1073741828, … },        // **按名字挑中本次这一份**
  "embeddedPickedBy":"name:file",                  // 挑不到时是 "fallback:first"，如实说
  "scriptCount":7, "mountKnown":true,
  "candidates":[ {"name":"表现 view.lua","mappingId":1073741828,"mappingMounted":true}, … ] }
```

`op=deploy` 的 `reconcile` 也照此改为**先按名字在多映射里挑**（挑不到才退回第一条，行为与旧版一致），
回执多给 `mappingId` / `mappingMatchedBy` / `mappingCount`。

> 复测口径（照 `docs/dsh-miliastra_多脚本配置实践与工具缺口_2026-09-25.md` §3）：
> ① `op=inspect file=主控 main.lua` → `mount.mounted:true`；② 把某脚本从容器「脚本」页签移除并存盘 →
> 该文件 `false`、其余仍 `true`；③ `op=script` 列出全部映射；④ 工作区 `tools/check-script-attach.mjs`
> 报「被 N 个控件引用 / 无引用」，解析失败时打印 `PARSE_FAILED` 且**不下结论**。

## 模拟器里的脚本：`op=patch` 的两个坑 + `op=bind` 多脚本（0.3.1，反馈 B1/B2/B4）

**实测事故**：用 `sourceFrom:"C:\\…\\表现 view.lua"` 挂 5 个脚本 → 5 个脚本全部在运行时报
`表现 view.lua:1: unfinished long string (starting at line 1) near <eof>`（**源码是空的**），
而这条错**只有脚本自己的 print 看得见**；`removeScript` 传 `path` 则报 `脚本不存在: undefined`。

| op | 现在支持 | 缺参数时 |
|---|---|---|
| `addScript` | `source`（内联源码）**或** `sourceFrom`（.lua 绝对路径，工具替你读，复用 `op=read` 的校验） | **明确拒绝**并列出「这次还传了哪些字段（它们不是源码字段）」—— **绝不写空脚本** |
| `updateScript` | 同上（`source` 可选）+ `id` **或** `path` | 缺 `id`（也可传 `path`） |
| `removeScript` | `id` **或** `path` | 找不到时 `未找到该脚本 "X" —— 现有脚本：a.lua(id) / b.lua(id)`（不再有 `undefined`） |

`op=bind` 一次挂多个脚本（多脚本工程不再要 `bind` + 多次 `patch`）：

```jsonc
{ "op":"bind",
  "scripts":[ {"path":"主控 main.lua","sourceFrom":"D:\\…\\主控 main.lua"},
              {"path":"表现 view.lua","sourceFrom":"D:\\…\\表现 view.lua"} ],
  "templates":[ {"guid":1073741868,"kind":"auto"} ] }
```

- 三类字段（`path` / `source` / `sourceFrom`）与 `op=patch addScript` **同名同义**（同一份实现，不会两处漂移）；
- `scripts[].path` 重复会被拒绝（同一工程里脚本路径必须唯一）；
- 回执多给 `sources[]`（每份的 bytes/lines/sha1_12）与 `scriptCount`，`source` 仍是**第一份**（向后兼容）；
- 配方 `last-bind.json` 记下 `scripts[]`（能按路径重读的就存路径，纯内联的才存源码）⇒ `last:true` 一键重搭。

## 按「局」读日志（`miliastra_log op=runs`）

**记录字段**（`op=tail` / `op=grep` 每条记录带的键）：`time`（**关卡加载时刻，不是记录时刻**）、`account`、
`player`、`channel`（试玩里是关卡名）、`message`。`op=errors` 另给 `run` / `fileLine{file,line}` / `kind`。
> ⚠️ 这一行原本写在工具 description 里，2026-09-30 为压 schema（32KB 棘轮）**下沉到这里** —— 内容一条没少。

**一个 `.gia` 里可以装多局**（实测 `21-24-16_155` 装了两段完整 `OnInit…OnDestroy`）。
以前只有整文件倒序的 `op=tail`，读的人得**人肉**把 30 多条倒过来、再分清哪段属于哪局。

`op=runs` 按 `instance` 第一段切局：

| `instance` 第一段 | 含义 |
|---|---|
| **`47504`** | **一次试玩运行** |
| `90003` | 编辑器主屏会话（跨多局不变） |

每局一行摘要：`epochSec`（**开跑时刻 —— 与 `miliastra_playtest` 报的是同一个值**）、`startedAt`、
记录数、**疑似异常次数**、**错误样式数**、首末行、就绪横幅；再给最近两局**局间 diff**
（新增/消失的错误样式 + `recordDelta`/`faultDelta`/`errorKindsDelta` + 一句 `verdict`）。

配套 `run=<epoch 秒或 instance 片段>`：`miliastra_log op=tail run=1790171162` 就**只看那一局**。

> ⚠️ `faultCount` / `errorSample` 是按**通用词**（重生/死亡/失败/`nil value`…）归的「**疑似**」计数，
> 不是平台给的分类 —— 回执里带 `caveat` 说明；具体含义以你脚本里那行 `print` 自己的文案为准。
>
> ★ **命中的词一并报出**（2026-09-25 同事实测：只有 `errorKinds: 2` 时，读的人判断不了该不该信这条归类）：
> `errorSample[].matched`（逐行，**只列真命中的**）、`errorMatched` / `faultMatched`（整局的词表，去重）。
> 计数判据一个字没改：`errorKinds` 仍是「去重后的错误行数」；词表与那条合并正则**同源**（由词表推导）。

## 从尾部读日志（`miliastra_log` 的 `last` / `from`）

**为什么有它**（2026-09-25 同事实测）：想看**收尾阶段**（那 141 条 Destroy 拒绝）却只能从头取 —— 一个文件末尾才是「这一局怎么结束的」。

```bash
miliastra_log op=tail last=3            # 只取尾部 3 条（收尾阶段的报错）
miliastra_log op=tail last=20 tag=Destroy
miliastra_log op=tail limit=50 from=head   # 从头取那 50 条
```

顺序**永远是 先过滤（`run` / `tag` / `pattern`）→ 再取尾**，返回仍按**时间正序**（最早在前）；
回执的 `window` 会如实报「这次是从哪一端取的、取了几条」。`limit` 的行为**一个字没改**
（超限时留最新的那些，默认 120）。`from` 只认 `end` / `head`，传别的**明确报错**。

## 关卡表几何事实（`miliastra_code op=levels`）

**为什么有它**：有一晚白跑了两局 —— 按设计文档的 ASCII 图**脑算**排坐标，结果 A 的横向占位 `[400,740]`
与 B 的 `[720,1060]` **水平投影重叠 20px**、A 最高时玩家头顶离 B 底面只剩 **6px**。
这两个数字**本来算得出来**，缺的只是「让工具读得到那张关卡表」。

```
miliastra_code op=levels            # 全部关卡
miliastra_code op=levels stage=3    # 只看第 3 关（序号或名字片段）
```

从活文件里抽 `local LEVELS = { … }`（**也认 `DATA.LEVELS = { … }`** —— 表挂在字段上的那种写法），每关给这些**数字**：

抽不到时会**列出候选**：回执带 `nameCandidates`（文件里像关卡表的声明 / 赋值，如 `local STAGES` / `DATA.LEVELS_2`，
带行号与 `kind`），把其中一个传给 `nameHint` 再跑一次即可（`nameHint` 默认 `LEVELS`）。

| 字段 | 是什么 |
|---|---|
| `plats` | 每块 `{ n, x, y, w, h, kind, kindName, mv, iso }`（`n` = 它在表里的 1-based 序号） |
| `facts.adjacent` | **相邻声明对**：`dxOverlap`（水平投影重叠 px）/ `dxGap`（缝 px）/ `dyRise`（后者高多少）/ `pattern`（如 `向上+水平重叠`） |
| `facts.risingOverlaps` | 其中形状是「**向上 + 水平重叠**」的那几对 —— **那次白跑就是这个形状** |
| `facts.nearMiss` | 两两之间「水平重叠 且 垂直净空 ≤ `nearPx`（默认 48）」→ `clearance` 就是「还剩几 px」 |
| `facts.overlaps` | 两块矩形**真的相交**（含 `dxOverlap × dyOverlap`） |
| `facts.kinds` / `bbox` / `spanX` / `spanY` | 分类计数与包围盒 |

> ★ **只报数字，不下判决。** 输出里**不出现** `pass` / `reachable` / `verdict` 这类字段 ——
> 「跳得过去吗」取决于跳跃初速、重力、移动平台相位，那是**玩法**，是你定的。
> `nearPx` 是筛选阈值不是判定；`adjacent` 按**声明顺序**（脚本注释说那是通关路径顺序）。
> （这条纪律有专门的测试守着：`leveldata-test.mjs` 里断言输出里没有判决字段。）

**解析边界**：只认**纯字面量表** —— 数字 / 字符串 / `true` / `false` / `nil` / 常量名
（含 `local A, B, C = 1, 2, 3` 这种多变量一行）/ 嵌套表 / 命名段 / 尾随逗号 / 行与长注释。
表里一旦出现**算出来的值**（算术、拼接、函数调用、变量引用），会**报行号 + 那一行原文**，
**绝不猜、也不静默少算一块**：

```
{ ok:false, error:"这一项不是字面量（认不出的写法：1+2）", line:76, lineText:"  { 1+2, 3, 4, 5, 0 }," }
```

**坐标口径**：按表里怎么写就怎么报（该表约定设计坐标 y 从顶向下）。脚本转控件坐标时会**翻 y**
（实测 `canvasH / 2 - dy * sy`）—— 回执里带 `coordinateNote` 提醒，**别直接和控件坐标比**。

**本机实测输出**（`双相.lua` v9.2）：

```
3 关，画布 1600×1000
  第1关 教学    ：平台 15（iso 1）bbox 1600×880  相邻重叠 1 处（向上重叠 0）真相交 0  净空≤48px 0
  第2关 长链    ：平台 30（iso 0）bbox 1600×550  相邻重叠 1 处（向上重叠 0）真相交 0  净空≤48px 0
  第3关 移动平台：平台 5 （iso 0）bbox 1600×560  相邻重叠 0 处                  真相交 0  净空≤48px 0
```

那两处「相邻重叠」都是**向下**的行间过渡（一处向下 140px、一处向下 460px），是正常的；
**「向上重叠」三关都是 0**。

## 指标汇总（`miliastra_log op=metrics`）

**为什么有它**：真正救命的常常不是几十条日志正文，而是脚本里**自己加的那一行**
（`落出边界 -> 重生（第 3 关，摔死处 x=814）`）。但这类埋点每次都要重新发明格式。
`op=metrics` 把它变成「一层约定 + 一层不用改代码的兜底」。

**① 严格约定**（可选）—— `[MIL]` 开头 + `k=v`：

```
[MIL] evt=death lv=3 x=814 stand=2
[MIL] evt=clear lv=3 ms=8420
[MIL] death lv=3 x=814          ← 事件名不带 evt= 也行（取第一个裸词）
```

| 键 | 含义 |
|---|---|
| `evt` / `event` / `e` | 事件名（缺省取第一个裸词） |
| `lv` | 关卡号（也认 `第 3 关`） |
| `x` / `y` | 位置 |
| `ms` | 耗时毫秒 |
| `n` | 计数 |
| 其它 | **原样保留**，工具不解释 |

→ 每个事件一张卡：次数 / **分关次数** / 数值字段的分布 + 一条时间线。

**② 宽松抽取**（**不用改脚本**）—— 任何日志行里出现 `k=<数字>` 就收，配上 `第 N 关` / `lv=N`
给出**按键**的分布与集中区。

### 两个「集中」指标，别混

| 字段 | 含义 | 抗离群值 |
|---|---|---|
| **`core`** | **四分位距 p25~p75**（中间 50% 落在哪） | ✅ —— 「集中在 700~860」用的是**这个** |
| `hotBin` | 直方图命中最多的那一箱（看形状） | ❌ 会被离群值摊薄 |

实测：12 个 x 跨 460~1086、其中 9 个挤在 694~860 时，`hotBin` 最多只装到 **3 个**，
而 `core` 给出 **706~825**。

**真机输出**（不用改脚本，直接跑现有日志）：

```
2026-09-23_21-46-05_157.gia：30 条记录，宽松命中 17 条（MIL 0 条，忽略 13 条）
  键 x    ：10 次，458~1011，中位数 623，**集中区 502.5~703**，热区 458~513.3
    第 3 关：10 次
  键 玩家x： 6 次，386~679，中位数 454.5，**集中区 454~455**，热区 444.6~473.9
```

> ★ **只报数字，不下判决**：输出里没有 `verdict`/`pass` 这类字段 ——
> 只说「N 次里有 M 次落在 a~b」，不说「这关有问题」（有测试守着这条）。
> 没有指标格式的行**一律静默忽略**（`ignored` 计数如实报出）；本 op **只读** `.gia`，一个字节都不写。

## 部署前的 Lua 结构校验（`lintMode`）

**一段语法错的 Lua 投进沙箱，试玩会静默不生效** —— 脚本根本没起来，日志里只会是「什么都没有」，
这是最难查的一类失败（比报错难查得多）。所以 `op=deploy` 默认先扫一遍结构：

| `lintMode` | 行为 |
|---|---|
| `strict`（默认） | 缺 `end` / 括号不配平 / 字符串或长注释没闭合 / `repeat` 少了 `until` → **直接拒绝部署，且不碰活文件、不产生备份** |
| `warn` | 照投，但把问题放进返回值的 `warnings[]`，不静默吞掉 |
| `off` | 不校验（逃生舱） |

校验器在 `lib/lualint.mjs`，**零依赖的结构级启发式**（不是完整 Lua 解析器）：先严格剥掉注释与
字符串（含 `--[[ ]]` / `[==[ ]==]` 长括号），再统计块开闭与括号配对，**报出「第 N 行的 xxx 没有对应的 end」**。

> ⚠️ 写它的时候踩过一个坑，值得记下来：最初「换行直接跳过」，结果**行尾标识符与下一行行首会粘成一个词**
> （`local sx, sy` 换行接 `local` → `sylocal`），行首的 `end` 被吞进上一行的尾巴 ——
> 于是**真文件恒报「缺 29 个 end」，而单行小样例却全绿**。现在换行会占位保留，
> `tests/lualint-test.mjs` 里有 4 条专门盯这个的回归断言。

典型循环：

```
miliastra_health                       # 我在哪张图、活文件是哪个、日志在哪
  → 改本地 .lua
  → miliastra_code op=deploy source=<本地路径>
  → （编辑器里）停止试玩 → 重新试玩
  → miliastra_log op=tail tag=<你的标签>
```

## UI 门禁（`miliastra_code op=lint-ui`，2026-09-26 P0-1）

> 这一节是**工具 schema 下沉下来的正文**：schema 里只留了判据骨架与指针，细则在这里。

**为什么要进插件**：这四条是**平台级、与玩法无关**的约束，之前每个千星工作区各自维护一份
`tools/check-ui-contract.mjs`（《侦探杀》工作区那份 293 行）—— 重复劳动，而且**判据必然漂移**。
其中第 ④ 条是「**离线唯一能拦**」的：真机上文本框矩形高容不下字号行高时，该控件
**一个像素都不画**（不裁切、不缩小、不报错，`visible` 仍为 true），而**模拟器不模拟这个截断**。

### 判据（回执里每条一个数组，元素 `{file,line,name,expected,actual,delta}` + `where`）

| 判据 | 键 | 口径 |
|---|---|---|
| ① 画在哪 = 点哪算 | `checks.pairsMismatch` | **人点名的**对照（`ovB1` ↔ `T_START` 这类异名，靠 `pairs` 给）必须**逐字一致** |
| ①b 同名跨文件差异 | `checks.sameNameDiff` | **只是事实**：不同界面复用同名控件是合法的 ⇒ **不计入 `passed`**（工具不猜语义） |
| ② 8 的倍数 | `checks.notMultipleOf8` | 坐标 / 尺寸必须是 `uiConfig.grid`（默认 8）的倍数 |
| ③ 字号四档 | `checks.badFontSize` | 只许 `64 / 52 / 28 / 22`（`uiConfig.fonts` 可覆盖） |
| ④ 文本框矩形高 | `checks.textTooShort` | `h ≥ 字号 × lineHeight(1.4)` **且** `h ≥ 字号 + slack(16)`；`makeBtn` 的文字按 28 号算 |

`passed` = **上面四条判据全满足**；它**不代表 UI 合格**（好看不好看、合不合适是作者的判断）。
回执里的 `disclaimer` / `passedMeans` 就是把这句话写在数据里。

### 作用域（`uiConfig.nameFilter`）—— 这一条最容易踩

基线工具只覆盖**覆盖层**那些名字（`ov|pk|cx|mx` 前缀 + 它硬编码的对照表），所以它在《侦探杀》上 0 问题；
同一份工程里**别的层**（图鉴 / 弹窗 / 开始场景 / HUD）本来就不在那些判据里。
本 op **不替任何玩法写死前缀**：`uiConfig.nameFilter` 收一个正则（默认 `null` = 全部名字）。
要在《侦探杀》上复现基线口径：

```
miliastra_code op=lint-ui dir=<code/侦探1> uiConfig={"nameFilter":"^(ov|pk|cx|mx)"}
  pairs=[{a:"btnSet",b:"BTN_SET",aFile:"调查板 board.lua",bFile:"交互 input.lua"}, …]
```

`pairs` 支持 `aFile` / `bFile`（文件名字串）——**同一个名字在不同界面里是不同控件**时，靠它把对照锁到文件。

### 认不出来的怎么办（不猜）

- 循环建出来的控件（`add(MENU_BTNS[i][1], "img", 620, y, 360, 72)`）**算不出矩形** ⇒ 进 `skipped`，不当成"合格"；
- 文本框但**字号认不出**（既没 `setFont` 也没 `.c.fontSize`）⇒ 进 `skipped`，**不拿默认值顶**；
- `pairs` 里点到的名字**找不到** ⇒ 进 `unresolved`（如实说找不到哪个），不假装比过。

### 没移植的（基线里那几条项目专有检查）

基线工具里 ⑨~⑫ 依赖《侦探杀》的变量名与布局（格盘 `CELL/GAP/GX/GY` 四方一致、1:2:1 三栏比例、
热区必须落在 `pL`/`pR` 内、逐个按钮的硬编码对照表），**通用化不了**，因此**没有**移植 ——
回执的 `portNote` 里如实写着，要那一层继续用工作区那份脚本。

> 这一节是 `miliastra_code` description 下沉下来的正文（2026-09-29 第四批）。**只报数字，不判决。**

## 试玩探针（`miliastra_probe`）的下沉原文

> 这一节是 `miliastra_probe` description 下沉下来的正文（2026-09-29 第四批）。

- **为什么需要它**：有些事**光读代码看不出来** —— 例如「OnInit / OnEnable 期能不能创建控件」「锚点是不是归一化 0..1」
  「某个按键枚举到底叫什么名」。这些只能让游戏真跑一遍，把答案 `print` 到 `.gia` 里。

  正文会先过一遍**结构校验**（**缺 `end` / 括号不配平 / 字符串没闭合直接拒绝渲染**）。

## 存盘快照的归属 / 部署目标 / 部署安全（下沉原文，2026-09-26）

> 这一节是 `miliastra_code` / `miliastra_health` / `miliastra_map` 的 description 下沉下来的正文。

- **存盘快照的归属（P0-2）**：`miliastra_map op=script` 与 `miliastra_health op=sha` 里 `.gil` 那一列
  **是编辑器存盘那一刻的快照**，不是实时的。两处都带 `belongsTo`（哪一次存盘：本地时间 + epoch 秒）、
  `belongsToAt` / `belongsToEpochSec`、`isCurrent`（与活文件 mtime 比：活文件更新 ⇒ `false`）与
  `currentnessNote`（人话：不一致就**去编辑器里存一次盘**）。**拿不到证据时 `isCurrent:null` 并明说「没有证据」**
  —— 与 `miliastra_log` 的 `staleLog` / `logBelongsTo` 同一个口径，绝不静默给旧数据。
- **选目标活文件只用名字，不按「最近改动」猜**。顺序：显式 `file` > `source` 的**同名**活文件（忽略大小写与 `.lua`）
  > 目录里**只有 1 个**活文件（允许，但回执带 `basenameMismatch:true`）> **拒绝写盘并列出全部候选**。
  回执**恒带** `dest` 与 `destBasenameMatchesSource`。
  实事故（2026-09-26）：多脚本工程里只给 `source` 时按 mtime 挑，把 `交互 input.lua` 的内容写进了 `表现 view.lua`。
- **安全约定**：活文件是**唯一副本**（没有 git、没有撤销）⇒ **备份失败就中止覆盖**；**原子写**（同目录临时文件 → fsync → rename）；
  写完必校验 SHA，不过**自动回滚**；备份就在活文件旁边 `_backup\`，每次两份（固定名 `<原名>.bak` + 带本地时间戳的历史）；
  `noBackup` 必须同时传 `allowNoBackup:true`；所有写操作都回执 `restoreWith`。
- **首次写入（`firstWrite`，P2-5）**：目标活文件原先 **0 字节 / 不存在** 时，回执带 `firstWrite:true` + `firstWriteNote`
  —— 这是该活文件的首次写入，**编辑器里记得存盘**（不存盘 `.gil` 就嵌不到这份脚本，表现是"部署了但什么都没发生"）。
- **`brief` 档（P1-4）**：`miliastra_health {brief:true}` 的 `luaFiles` 是 `[{name, bytes}]`；
  `bytes === 0`（空脚本/未写入）与**不在 `.gil` 挂载集合里**的活文件都在 `note` 里点名（挂载表读不到就 `mountKnown:false`，一个都不标）。
  ⚠️ 这一档**必须继续 < 1KB**，所以标记只在出问题时才加、名单最多列 3 个。

## 素材库（`miliastra_asset`）

> 一节讲三件事：**怎么放**（入库）、**怎么引用**（取回）、**怎么清理**（删的口径）。
> 它是**插件级**的通用存储 —— 与玩法无关：UI 动画、粒子、像素画都只是"要存图片、要反复引用"的同一个需求。

### 为什么不塞进 `miliastra_code`

`miliastra_code` 管的是**沙箱里的活文件 `.lua`**：`source` 指脚本、失败模式是"覆盖唯一副本"、
纪律是"先备份再写"。素材库管的是**图片字节**：`source` 指图片、失败模式是"存的图找不回来"、
纪律是"按内容寻址 + 绝不自动删"。两套纪律塞进一个工具，AI 看到 `source` 就得先想"这次是 `.lua` 还是 `.png`"。
⇒ 单开一个工具，用有限 schema 体积换**语义不串门**。

### 怎么放：内容寻址

```
<数据目录>/assets/                 ← 数据目录 = MILIASTRA_DATA_DIR > DSH_HOME/miliastra > ~/.dsh/miliastra
  index.json                       ← 索引（原子写、无 BOM）
  86ac6118dd71f922.png             ← 素材正文：文件名 = sha256 的**前 16 位** + 原扩展名
```

三条设计决策与理由（都写在 `lib/assets.mjs` 文件头，这里给结论）：

| 决策 | 值 | 理由 |
|---|---|---|
| `id` 长度 | **`sha256` 前 16 位（64 bit）** | 生日碰撞概率 ≈ n²/2^65：**100 万**张也只有 ≈ 2.7e-8。而且**不靠概率兜底** —— 索引里存着**完整 `sha256`**，真撞上（同 id、不同内容）`add` 会**报错拒绝**，绝不覆盖。16 位是"短到能一眼读"与"不可能撞"的折中 |
| 单张上限 | **64 MiB** | 这是**素材**（界面图/像素画/精灵图），不是视频仓库。上限挡住"误把整个安装目录塞进来"，也让 base64 那条路（体积 ×4/3）在内存里可控 |
| 收什么 | 白名单 `png/jpg/jpeg/gif/webp/bmp/svg/ico/avif`；**拒绝 0 字节** | 白名单顺带给出 `mime`，于是 `get` 能直接回可用的 `dataUrl`（不用猜类型）。0 字节的空图没有任何意义，只会让库里攒出打不开的东西 |

入库三条路（`op=add`，三选一）：

```jsonc
{"op":"add","source":"D:\\art\\bg.png","tags":"背景,像素画"}   // ① 绝对路径（相对路径明确拒绝）
{"op":"add","base64":"iVBORw0KG…","name":"像素画.png"}          // ② 裸 base64（要给 name，否则认不出类型）
{"op":"add","source":"data:image/png;base64,iVBORw0KG…"}       // ③ data URL（mime 定类型）
```

**同内容再加一次 = 命中已有**（`deduped:true`，一个字节都不重写）；顺手带的新 `tags` 会**并进**那条记录。
`name` 只是**展示用**的原始文件名（会进索引、回在 `list` 里），**不参与寻址**，也不会被当成路径。

> **索引是缓存、目录才是真相。** `index.json` 丢了 / 写坏了 / 被人手改了都不算事故：
> `{"op":"rebuild"}` 会**读每个文件的字节现算 sha256** 重建索引（这正是内容寻址的好处 —— 目录本身携带全部真相）。
> 重建时**目录说明得了的字段照实填**（`sha256`/`bytes`/`ext`/`mime`/`id`），
> **说明不了的如实标 `null`**（原始文件名 / 来源 / 加入时间）—— 不编。

### 怎么引用

```jsonc
{"op":"get","id":"86ac6118dd71f922"}                 // 回 dataUrl（可直接喂图片查看器）
{"op":"get","id":"86ac", "out":"D:\\out\\bg.png"}     // 或写到指定绝对路径（逐字节一致）
{"op":"list","tag":"背景","summaryOnly":true}          // 先看总数与总体积
```

- `id` 可以给**唯一前缀**（`86ac` 够用就行）：命中多条会**报候选、不猜**。
- `get` 写 `out` 时，目标**已存在默认不覆盖**（要盖传 `overwrite:true`）——
  这是「磁盘是用户的」那条规矩在**写**这一侧的对称面：不声不响盖掉别人的文件，和删掉它一样糟。
- 取回时**会重算 sha256 并与索引比对**：对不上（索引过期 / 文件被换过）就 **`ok:false` 且不写出去**。

### 怎么清理（**磁盘是用户的**）

| 动作 | 默认行为 | 真要动盘 |
|---|---|---|
| `op=remove id=…` | **什么都不动**，回 `ok:false` + `needsConfirm:true` | `confirm:true` = **只摘索引**（字节留着）；再加 `deleteFile:true` 才删字节 |
| `op=prune` | **只报告**（`dryRun:true`）三类：`missing` 索引有字节没、`orphans` 字节有索引没、`corrupt` 字节与 sha256 不符 | `confirm:true` 只删上面点名的**无主 / 损坏**两类，正常素材一个都不碰；删完自动重建索引 |

- **没有批量静默删的口子** —— `remove` 一次只认一个 `id`，还得显式确认。
- 只摘索引的素材会变成"无主文件"，`prune` 能看见它、`rebuild` 会把它**收回来**（这就是"只摘索引"的语义）。
- 素材**只写插件自己的数据目录**：不进游戏存档、不碰活文件。

### 边界（这一层**不做**什么）

- 不做图片解码 / 缩放 / 格式转换（要处理就取出来自己处理）；不校验字节**真的是不是**那个格式
  （只按扩展名与 `mime` 归类 —— 内容真有问题是**取出去用的时候**才会暴露）。
- 不做引用计数：素材被删不影响已经 `get` 出去的文件。
- 与真机的关系：这是**本机素材库**，把图变成游戏内可用的**图片资产 ID** 仍然是编辑器里人做的事
  （见工作区 `AGENTS.md` 的铁律：图片资产 ID 必须由创作者交接）。

### `op=catalog`：图片资源库怎么用

```jsonc
{"op":"catalog","category":"基础形状"}                    // 分类 id / 中文名 / 英文名都能给
{"op":"catalog","colorKind":"mono","summaryOnly":true}    // 只要"可染色那批"的计数 + 分类表，不要 1543 条
{"op":"catalog","simOnly":true}                           // 只列模拟器画得出来的 6 个几何号
{"op":"catalog","imgExists":false}                        // 只看 21 条"目录里有、图却缺"的
{"op":"catalog","id":100136}                              // 按素材号精确查一条
```

回执：`{ok, op, filters, categories?|category?|categoriesOmitted?, items?|itemsOmitted, counts, limit, limitClamped, idRange, source, unverified, notes}`。

- **回执体积策略（2026-09-28 · 作者点名的 AI 侧体验）：发现调用给全表，过滤调用只给结论。**
  | 调用形态 | 分类表 | `source` |
  |---|---|---|
  | **发现调用**（`category`/`colorKind`/`simOnly`/`imgExists`/`id` **全空**） | 完整 **14 行** | 3 字段 |
  | **过滤调用**（给了任一收窄条件） | **省掉**，改回**单条** `category:{id,nameZh,nameEn,count,range}`（仅在 `category` 收窄到一个分类时）+ `categoriesOmitted:14`；子串命中多个分类（如「单色」→ 4 个）时给那 4 行 + `categoriesOmitted:10` | 3 字段 |
  | **`withMeta:true`** | 完整 **14 行**（**显式要就给**） | 3 字段 + `sha256Prefix`（三连，各前 10 位）+ `fetchedAt` |

  `source` 恒为 **3 个字段** `mirror` / `origin` / `note`（`note` = `镜像 ≠ 官方（第三方镜像，非 miHoYo 端点）` 一行；
  镜像主机与目录在 `origin` 里，**结论一个没少**）。实测：查一个分类（6 条结果）时，14 行分类表约占回执**一半**。
  ⚠️ **只去体积、不去结论**：`counts`（`total`/`returned`/`truncated`/`catalogTotal`/`imgMissingInCatalog`）、
  `filters`、`limit`/`limitClamped`、`idRange`、`notes`、`unverified`（**对外诚实口径，任何模式都在**）一个都不少 ——
  `tests/catalog-test.mjs` 的 ⑤ 断言把「同一条件下 `counts` 在精简与 `withMeta` 两种回执里逐字段相等」钉住。
- **`category` 支持子串**：`"单色"` → 命中 4 个分类（`filters.categoryIds` 里看得见是哪几个）；
  **一个都没命中就报错并列出全部合法值**（不静默回落全表）。
- **`imgExists` 是必须看的一列**：目录里有 **21 条**的 `img`/`border` 是空串，实测其 PNG **404**
  （`101019 101029 101047 101049 101055 105141 105220 106048 107008 107009 107093 107181 107182
  107202 107206 107229 107230 107279 108018 109032 109035`）⇒ 拿号去 `SetImage` 之前先筛 `imgExists:true`。
- **`simRenderable` = 我们自己的模拟器认不认**（只有 `100001~100006` 会被画成程序化图元，其余画"缺图"标记）。
  这条**不是**"官方素材长什么样"—— 模拟器不加载 PNG。测试直接读 `engine/studio/constants.js` 的
  `IMAGE_PRIMITIVES` 核对，防两边常量漂移。
- ★ **E1③（2026-09-30）：图片控件的 `primitive` 现在分三档，不再"补方块"**（`imagePrimitiveOf()` 一处规则、四处调用点共用）：
  | `imageId` | `primitive` | 画成什么 | 含义 |
  |---|---|---|---|
  | `100001~100006` | 各自的形状名 | 程序化图元（方块/圆/三角…） | 模拟器画得出来，真机也有这 6 个几何素材 |
  | **空 / 0** | `missing` | 深灰底 + **红框** + 白 `?` | **模板没指定贴图** —— **真机同样是 `?`**（这就是 E1 那个"离线全绿、真机满屏问号"的坑） |
  | 有号但不是这 6 个（如 `101023`） | `unsupported` | 深灰底 + **蓝框** + 白 `?` | **真机有图，模拟器画不出来**（不加载 PNG）—— 与上一档分开，免得冤枉成"缺贴图" |
  ⚠️ 在这之前，作者层默认 `imageId = 100001`（方块）⇒ 模拟器自己补一张方块，把真机症状**完全盖住**。
  现在**未指定就是未指定**；要显式要一块方块：脚本里 `c:SetImage(Enum.ImageSource.StaticReference, 100001)`，
  或模拟器里 `patch add {kind:"image", imageId:100001}`。

- **单张图片没有名字**：目录里**只有** `id`/`img`/`border`（1543 条全量核对，无 `name`/`title` 类字段）
  ⇒ 回执只给**分类名**，**绝不编"`100136` = 星星"**这种话。要单图长什么样只能人去编辑器里看。

### `op=sound-search` / `op=sound-get`：音效库怎么用

```jsonc
{"op":"sound-search","q":"宝箱 开启","limit":5}   // 空格分隔多个关键词 = AND（0 命中时 hint 会说"去掉一个词再试"）
{"op":"sound-search","q":"宝箱"}                  // 15 条，首条 50214 场景物件_机关交互_宝箱_01
{"op":"sound-search","q":"attack","category":"4"} // 按分类 id 限定（1 环境 … 7 操控对象）
{"op":"sound-search"}                             // 发现调用：只回 7 行分类表 + 快照元信息，**一条音效都不回**
{"op":"sound-search","q":"宝箱","withMeta":true}   // 要完整分类表 / 快照元信息时显式开
{"op":"sound-get","id":"50214"}                   // 单条详情（含 durationMs，单位毫秒）
```

- **回执体积策略**（与 `op=catalog` 同一套口径）：**发现调用给全表、过滤调用只给结论**。
  | 调用形态 | 7 行分类表 | `catalog` 元信息 |
  |---|---|---|
  | **发现调用**（没传 `q`；`browse:true`、`total:0`、**0 条音效**） | 给 | 给 |
  | **过滤调用**（带 `q`） | 不给 ⇒ `categoriesOmitted:7`（若给了 `category` 则**只给那一条** + `categoriesOmitted:6`） | 不给 ⇒ `catalogOmitted:true` |
  | **`withMeta:true`** | 给 | 给 |

  省下来的正是"每次回执都重复带整张表"那部分（实测查 3 条音效时分类表 + 元信息约占回执 **45%**）。
  ⚠️ **只去体积、不去结论**：`total` / `truncated` / `limit` / `limitClamped` / `weak` / `hint` 一个都不少。
  `op=sound-get` **本来就没有**分类表与元信息（实测 208 B）⇒ 不需要 `withMeta`。
- **五档相关性**（顺序即优先级，逐条给 `matchKind`）：
  `exact > prefix > substring > subsequence > editDistance`；档内再按 `score`（整数、可复现）。
  **档位 = "有多可信"**，AI 只看前几条就够（实测 `环境 风声` 的 `total=28` 里，第 4 条起全是 L5 噪声，排在最后）。
- **归一化口径**：小写 + 全角转半角 + **只留 `[a-z0-9]` 与 CJK** ⇒ `环境_震动` / `环境 震动` / `（环境震动）` 等价，
  `Environment_Vibration` 与 `environment vibration` 等价。多关键词是 **AND**。
- ⛔ **不支持拼音 / 首字母缩写**（本机**没有**拼音词表）：`宝箱` ✅、`baoxiang` ❌ 0 命中、`bx` ❌ 不是"宝箱"
  （247 条是子序列凑的）。**0 命中的 `hint` 按分支说人话**：只有「单词 + 纯拉丁字母」那一支才念这句长话，
  其余分支不重复念（免得每轮都在花没有用的上下文）。
- **0 命中时 `hint` 的三条支路**（**首要建议放最前面**，作者 2026-09-28 点名）：
  | 查询形态 | 首要建议 |
  |---|---|
  | **≥2 个词** | 「**多关键词是 AND（全都要命中）** —— 去掉一个词再试（例如只搜「第一个词」）」；其次换英文名 / 用 `category` 限定 |
  | **1 个词 + 含 CJK** | 「换更短的词 / 试英文名 / 用 `category` 限定；也可以用 `sound-get` 直接按 id 取」 |
  | **1 个词 + 纯拉丁** | 「⚠️ **不支持拼音/首字母**（没有词表），别试 `bx`/`baoxiang`」 |
  | **`weak:true`**（有命中但最弱档） | 保留原有那句「这批是"凑"出来的」—— **不被上面覆盖** |

  为什么多词那条排第一：`{"q":"攻击 命中"}`（两个中文词的 AND）实测 0 命中，而最该说的是"去掉一个词"，
  旧版 `hint` 却只讲"不支持拼音 / 用分类 / 用 id"。
- `weak:true` = 最弱档已是 `subsequence`/`editDistance` ⇒ **这批是"凑"出来的**，不算名字命中（`hint` 里也说了）。
- `limit` 默认 20 / 上限 100；`category` 非法**报错并列出合法 id**；
  **没传 `q` 不报错** —— 那是发现调用（给分类表 + `browse:true` + **0 条音效**，绝不静默回 1997 条）；
  `q` 全是标点仍**报错**（`tokenizeQuery` 给不出有效关键词）。
- `op=sound-get` 找不到**不抛错**（回 `found:false` + `hint`）；`id` 为空才报错。

### 两个通道共同的纪律

- **只报事实、不下判决**：回什么 id、什么档、有没有图、认不认，都是事实；"该用哪张 / 该配哪条"是作者的事。
- **`summaryOnly` 只去体积不去结论**：省掉逐条 `items`，`counts` / `categories` / `unverified` / `source` 一个不删。
- **回执里没有 `undefined`**（该没有的一律 `null`），有测试钉住（`JSON.stringify` 会把 `undefined` 键整键删掉，
  那种"字段悄悄消失"最难发现）。
- **素材边界**：本仓库**不打包**任何第三方素材内容，也**不抓**对方 CDN 的素材本体 —— 只有数字与分类事实。

### 未验证项（回执恒带 `unverified[]`，别当结论用）

| 项 | 状态 | 说明 |

### `output` 三种取值

| `output` | 回执 | 什么时候用 |
|---|---|---|
| **`"lua"`（默认）** | **可直接部署的 Lua 源码**（`lua` + `luaBytes` + `lines`）+ 统计 + `nextStep` + `warnings[]` | 这就是默认路径：**一次调用 → 拿去 deploy** |
| `"data"` | 结构化数据（`text-gradient` 给 `frames[].lines` 逐帧正文；`pixel-art` 给 `blockList` 块表），没有 Lua | 要给面板用 / 要自己二次加工 |
| `"struct"` | 千星变量 JSON（**只有 `pixel-art` 用**；形态与源码 `downloadJson` 逐字一致） | 要在编辑器里建/导入结构体变量 |

`struct-json` 的产物**本来就是 JSON**（千星变量导入格式），不受 `output` 影响，但它照样给 `nextStep`。

### 交接值（AI 拿不到的东西）—— **先自动拿，拿不到就报错点名**

生成的 Lua 要改**哪一个控件**，这件事 AI 从参数里推不出来：

| 交接值 | 参数 | 谁用 | 生成的 Lua 怎么用它 |
|---|---|---|---|
| **文本框控件名**（推荐） | `controlName` | `text-gradient` | `script.object:GetChild(CONFIG.CONTROL_NAME)` —— 脚本挂在**容器节点**上，从它的**直接子控件**里按名字找 |
| **控件模板索引** | `templateIndex` | `text-gradient` / `pixel-art` | `game.InstantiateClientUIControl(CONFIG.TEMPLATE_INDEX, host)` 动态建（只有「存为模板」的独立控件建得出来）；`pixel-art` 要的是**图片**控件模板 |
| **容器节点索引** | `container` | `pixel-art` | 只进 `CONFIG.CONTAINER_INDEX`：`OnStart` 的 `start ver=… container=…` 日志用它**自证脚本挂在哪**（官方没有"按索引取容器"的接口，父级一律用 `script.object`） |

- `text-gradient`：两个文本框交接值都给 ⇒ **用 `controlName`**（回执 `warnings[]` 里明说 `templateIndex` 被忽略）。
- **都没给** ⇒ 工具**先自己读当前关卡的 `.gil`**（本仓既定顺序：① 自动拿 → ② 拿不到才问人）：
  - `text-gradient`：`.gil` 里若恰有 **1 个**有名字的容器子控件 → 采用它的名字（`handoverFrom:"gil"` + 一条 `HANDOVER_AUTO_FROM_GIL` 警告，提醒部署前与创作者核一眼）；
    若没有有名字的子控件、而 `文本框` 模板恰有 **1 个** → 采用它的模板索引；
  - `pixel-art`：`.gil` 里 `图片` 模板恰有 **1 个** → 采用它的模板索引；独立的 `容器节点` 恰有 **1 个** → 采用它当容器（**两个各自独立判定**，一个拿到一个没拿到就只补那一个，`handoverFrom` 会标 `gil+arg`）；
  - **多候选 / 一个都没有** ⇒ **`ok:false` + `needsHandover[]` + `handoverCandidates[]`**（把 `.gil` 里读到的清单原样交回），
    错误文案直接说「**别自己编**」。
- ⚠️ `.gil` 的控件记录只有 `{id, name, parent, children}` —— **没有控件类型字段**，所以候选字段叫
  `namedChildrenOfContainer` / `imageTemplates` / `containerNodes`（**不叫** "textboxes"）：哪个是文本框、哪个是图片模板，
  要创作者确认，工具**不替你认**（名字叫 `图片` 只是"创作者按类型名起的名"这个**启发式**，且**只有唯一候选才采用**）。
- ★ **生成的 Lua 自己也会在运行时 `error` 点名**（`CONFIG.CONTROL_NAME == ""` / 找不到控件 / 不是文本框 / 实例化返回 nil），
  所以**不要把缺交接值的 Lua 直接拿去试玩** —— 那是本仓最忌讳的"让人试一个已知会崩的版本"。

### 生成的 Lua 长什么样（遵本仓 Lua 铁律）

```lua
local VER = "text-gradient/flow-forward/7f"
local CONFIG = {
    CONTROL_NAME = "标题",   -- 交接值；留空脚本会 error 点名
    FPS = 8,
}
local FRAMES = { "<color=#ffcc33>原</color>…", … }   -- 逐帧正文（一帧一行，已把 999 分段拼回）
```

- `OnStart`：`print` 一行**版本行**（`start ver=… frames=…`，事后看 `.gia` 就知道这局跑的是哪版）+ **`script:EnableUpdate(true)`**
  （本仓真机实测：不开这一句 `OnUpdate` **永不触发**）。
- `OnUpdate(dt)`：**第一帧立刻上屏**（不等累积，否则先空一拍）；之后按 `1/CONFIG.FPS` 累积换帧、`frame = (frame+1) % #FRAMES` 循环。
- **⛔ 没有任何"掩盖报错的兜底"**：没有 `pcall` 吞异常、没有静默 `return`、没有屏幕诊断串；拿不到控件就 `error("…")` 并点名。
- **交接值与节奏全在顶部 `CONFIG`**（不写裸数字魔法值）。
- 挂法：挂到「客户端控件容器 → 容器节点」这一层的**客户端脚本**上。
- **帧一帧都不少**：`output:"data"` 有「不给 `frames` 就只出前 60 帧」的上限，**`output:"lua"` 不吃这个上限**
  （动画缺帧就是静默截断）—— 这一条有测试钉住（79 帧的夹具 ⇒ Lua 里 79 条）。
- 想确认落地动作：回执的 `nextStep` 直接写着
  「用 `miliastra_code op=deploy` 投到活文件（**必须显式传 `level` 与 `file`**），然后在编辑器里**存一次盘**再试玩」。

### `op=text-gradient` 的逐帧算法（`output:"data"` 或 Lua 的正文都来自它）

把文本按字符切分 → 色标采样 → 风格动画 → 逐帧富文本（`<color=#RRGGBB>字</color>`）。

| 风格 | 值 | 帧数 | 一句话 |
|---|---|---|---|
| 颜色·普通 | `flat` | 1 | 按字符位置在色标上均匀取色（`t = i/(n-1)`；`n=1` 时 `t` 退化成 0） |
| 颜色·流动1 | `flow-forward` | `2n-1`（步长 1） | 「来回长序列 + 滑动窗口」，颜色沿字符方向流 |
| 颜色·流动2 | `flow-backward` | 同上 | 同一长序列，窗口从 `2n-2` **递减** ⇒ 反向流 |
| 颜色·淡入/淡出 | `fade-in` / `fade-out` | 固定 **24** | 逐帧乘整体 alpha：`i/23` 与 `(23-i)/23` |
| 字号·普通 | `flat` | 1 | 按 `sizes[]` 分段线性插值 |
| 字号·跳字 | `jitter` | **跟颜色帧数**（源码如此） | 每帧随机挑 **50** 个字符改成 `[sizeMin,sizeMax]`（默认 20~40），其余恒为 20 |

- **帧数** = `lcm(颜色帧数, 字号帧数)`（源码用 `lcm` 求公共循环周期）；`text:""` ⇒ 帧数 0。
- **输出分段**：单行超过 **999** 字符就换行（源码的 `getCharList`）。这是**输出分段**，不是平台限制。
- **`colorJumpFrames`**：步长 = `max(1, 值+1)`，越大帧越少（源码的 `frameSpeed`）。
  ⚠️ 源码 UI 上还有一个「大小跳帧」，但**算法里从未用过它** ⇒ 本工具也不暴露它（`notes` 里不假装有）。
- **枚举名是我们自己起的**（源码内部名 `ColorFlow1`/`ColorFlow2`/`Jump1` 未照抄）；传源码那个名字会**报错并列出合法值**。

### `op=pixel-art` —— 图片 → 可部署的像素画 Lua（2026-09-29 · 第四批）

> **移植出处**：`xiaomoL444/ugc-tool` 的 `src/views/PixelArt/PixelArt.vue`（作者已授权、**唯一要求保持开源**）。
> **只移植算法**；那份 Lua 是**本仓自己写的驾驶层**（源码走 `script:GetParam("ImagePrefebID"/"CenterOffsetX"/"CenterOffsetY"/"PixelSize")`
> 读编辑器参数，本仓改成顶部 `CONFIG` 常量 —— 因为 AI 交接的索引本来就来自调用参数）。
> 分层：`lib/pixelart/model.mjs`（常量/量化/参数校验）→ `decode.mjs`（关平滑降采样）→ `blocks.mjs`（行程与块合并）
> → `lua.mjs` / `struct.mjs`（序列化）→ `index.mjs`（编排 + 回执）。

**产物形态**：图片控件的**矩形块拼图** —— **不是"一个像素一个控件"**。
「关平滑降采样 → 行内行程 + **跨行同色同宽**合并」把 16×16 的图压成 4 个块（见下面端到端那组数），
所以一幅像素画的控件数 ≈ 色块数，不是格数。

#### 参数（**schema 里只有一句"干什么用"；默认值 / 边界 / 细则在这张表**）

| 参数 | 默认 / 边界 | 细节 |
|---|---|---|
| `assetId` \| `source` | 二选一 | 图源：素材库 id（**内容寻址**，支持唯一前缀）或图片**绝对路径**。两个都给 / 都不给都**报错**；**不抓网图**（不连任何第三方 CDN） |
| `cols` / `rows` | 1~512 | 网格（格）。**两个都给**=原样；**只给一个**=按原图宽高比推另一个（`gridFrom:"aspect"`）；非整数 / 0 / 超限**直接报错** |
| `maxSide` | 32 | 只给**长边**格数，另一边按原图比例推（`gridFrom:"maxSide"`）。**一个都不给**时按 32 兜底，`gridFrom` 会**如实标 `default`** 并给一条 `GRID_DEFAULTED` 警告（不假装是你给的） |
| `pixelSize` | **8**（1~64） | 一个格子在画布上占多少像素。⚠️ **与源码的刻意偏差**：源码 `GetParam` 缺省是 **1**，1 时一整幅 20×20 的画只有 20 像素宽、画面上几乎看不见；本仓 UI 栅格也是 8 的倍数。用默认值的调用会在回执 `deviations[]` 里标 `used:true` |
| `centerOffsetX` / `centerOffsetY` | 0（±4096） | 像素画中心相对**容器中心**的偏移（画布单位） |
| `templateIndex` | **交接值** | **图片**控件的控件模板索引。缺 ⇒ `ok:false` + `needsHandover[]` |
| `container` | **交接值** | **容器节点索引**（脚本挂载处）。缺 ⇒ 同上 |
| `imageType` | `Stretch` | `Enum.ImageType`，官方 7.1 原文**只有 `Stretch` / `Basic`**；其它值报错 |
| `use4bit` | `false` | 每通道量化到 `Math.round(v/17)`（0–15 级）**并铺回 0..255** 写进 `Color.FromRGBA`。官方原文 `4bit`/`#RGB` **0 命中** ⇒ 产物顶部加警示行 + 回执 `unverified[]` |
| `mergeRuns` | `true` | 行内行程 + 跨行同色同宽合并；`false` = 一格一个控件（块数会暴涨，**本仓新增开关**，源码恒合并） |
| `summaryOnly` | `false` | 只去正文：`lua` 去 `lua`、`data` 去 `blockList`、`struct` 去 `structText`/`struct`（换字节数）。统计 / `nextStep` / `warnings[]` **必须留** |
| `structId` | `1077936129` | 只有 `output:"struct"` 用；**必须 10 位数字**（与 `struct-json` 同一条硬规则），不合法 ⇒ `ok:false` + `needsHandover[]` |

#### 回执里那几个数

- `blocks` / `controls`：**相等**（一个块 = 一个图片控件），并在 `stats` 里给 `widestBlock` / `tallestBlock` /
  `transparentCells` / `distinctColors` / `mergeRatio`（只报数字，不下判决）。
- `warnings[]` 可能出现的：`INSTANTIATE_IN_ONSTART`（**恒有**：整幅画建在 `OnStart` 的循环里 ⇒ 命中本仓
  「构建期实例化」那条已知坑，见 §已知坑；真机若"整幅都不显示"，把创建挪到渲染第一帧再看一次）、
  `HANDOVER_AUTO_FROM_GIL`、`GRID_DEFAULTED` / `GRID_FROM_ASPECT`、`TRANSPARENT_CELLS_DROPPED`
  （`a=0` 的格子**不建块** —— 源码原判据 `if color[3] > 0`；千星没有"透明图片控件"）、`MANY_CONTROLS`（块数 > 512）。
- `unverified[]`：**恒有**「真机渲染」那条（离线只验到模型层与模拟器渲染）；开 4bit 时另加一条并写清依据。

#### 生成的 Lua（**静态**，所以**没有 tick**）

```lua
local VER = "pixel-art/16x16/4b"
local CONFIG = {
    TEMPLATE_INDEX = 1073741900,   -- 交接值
    CONTAINER_INDEX = 1073741866,  -- 交接值（只用于 start 日志自证挂在哪）
    COLS = 16, ROWS = 16,
    PIXEL_SIZE = 24,
    CENTER_OFFSET_X = 0, CENTER_OFFSET_Y = 0,
    IMAGE_TYPE = "Stretch",
}
local BLOCKS = { {0,0,8,8,255,0,0,255}, … }   -- {x,y,w,h,r,g,b,a}：格坐标左上原点、w/h 是格数
```

- ★ **不调 `script:EnableUpdate(true)`**、**没有 `OnUpdate`**：像素画是**静态**的 —— 建完就不动，
  开着 tick 只会每帧白烧预算。产物顶部有一行注释**说明这个理由**（免得下一个人以为是漏了）。
  ⇒ 真要做动画，自己加 `OnUpdate` 再开。
- **没有 `pcall`、没有静默 `return`、没有屏幕诊断串**；`script.object == nil` /
  `CONFIG.TEMPLATE_INDEX == nil` / `InstantiateClientUIControl` 返回 nil 全部 `error("…")` **点名**（带模板号与第几块）。
- 颜色走**字段** `imageColor`：官方 7.1 原文里 **`SetImageColor` 命中 0**（已逐条核过），所以只能赋字段。
- 几何：`SetAnchorMin/Max(0.5,0.5)` + `SetPivot(0.5,0.5)` + `SetSizeDelta(w×pixelSize, h×pixelSize)` +
  `SetAnchoredPosition((x + w/2 − COLS/2 − OX)×pixelSize, (ROWS/2 − y − h/2 − OY)×pixelSize)`（与源码同一条公式；
  y 取负是因为**画布 y 向上**，而格坐标是左上原点）。

#### `output:"struct"` 的形态（与源码 `downloadJson` 逐字一致）

```json
{ "structId": "1077936129", "type": "Struct",
  "value": [ { "param_type": "StringList", "value": ["<color=#FF0000FF>██</color>", "<color=#0000FFFF>█</color>　"] } ] }
```

- 一段 = **一行里的一段富文本**；同色连续段包成 `<color=#RRGGBBAA>█…</color>`；**完全透明**的段换成**全角空格** `　`
  （源码 `processColorTags` 的结果，`isUseSpace` 默认开）。
- 切段受**两个上限**：源码的「每行最大像素宽」（内部 `maxPixelWidth` 默认 40）+ 千星的「**单条文本 ≤500 字符**」。
  ⚠️ 源码只有前一个上限 —— 逐字符拼装做不到"按段裁"，一行 512 格同色会算到 537 字符而**超限**（测试钉住了这条）。

#### 与源码的**刻意偏差**（回执 `deviations[]` 会逐条列出，别以为全是照抄）

1. **默认 `pixelSize=8`**（源码 `GetParam` 缺省 1）—— 理由见上表。
2. **`use4bit` 同时量化 `Color.FromRGBA` 的入参**（`round(v/17)*17`）：源码里它**只影响那段富文本**
   （`mergePixels` 用的是原始 RGBA）—— 不量化的话 `output:"lua"` 下这个开关等于**空转**。
3. **alpha 固定写 8 位**（源码默认 `isUseAlpha=true`，但没把开关暴露到 UI 之外）。
4. **`mergeRuns:false` 是本仓新增**（源码恒做合并）。
5. `struct` 模式的**段长上限**多了一条「≤500 字符」（源码没有）。

#### 端到端证据（模拟器，`tests/pixelart-test.mjs` 里那条必须绿的用例）

自造一张 64×64 的图（四象限纯红/绿/蓝/黄 + 中间 4px 透明竖条）→ `cols:16 / pixelSize:24` →
模拟器 `op=bind` 跑起来 → **`built controls=4`**、运行时控件数 = 容器 + 4 → PNG 里：

| 事实 | 数字 |
|---|---|
| 与**空场景**的像素差 | **138 240 px**（== `Σ(w×h) × pixelSize²` = 240 格 × 576） |
| 变化区域（包围盒） | `608,258,384×384`（== 16×24 的正方形，居中） |
| 被透掉那格留下的缝 | **24 px**（== 1 格 × pixelSize；缝里逐像素与空场景一致 ⇒ 真的没建控件） |
| 逐块颜色 | 每一块**中心点**采样都等于 `blockList[].rgba` |
| 帧间像素差（0 → 0.5s） | **0**（静态 ⇒ 不该开 tick 的直接证据） |

⚠️ 这张表是**模拟器离线渲染**的结论：**模拟器通过 ≠ 真机通过**（官方素材 / 真机渲染管线 / 联机 / 手感都不覆盖）。

### `op=struct-json` —— 可直接导入千星的变量 JSON

#### ⚠️ 两样**未经真机验证**的能力（**默认关**）

| 能力 | 参数 | 官方依据 |
|---|---|---|
| `<size=N>…</size>` | `withSize:true` | 我核过的 **19 份官方 7.1 原文**里 `<size` **0 命中**（`<color` 命中 1 处） |
| 4bit 短格式 `#RGB`/`#RGBA` | `use4bit:true` | 官方只给了 `#FFFFFF` **六位**；`4bit` / `#RGB` 在原文里 **0 命中** |

- 官方**有**依据的那一条是 `<color=#RRGGBB>…</color>`（`docs/官方文档-7.1正式/原文/doc_界面布局.txt`），所以它是默认形态。
- 打开上面任一项，回执里就会出现 `unverified[]`（带 `what` / `why` / `param`）—— **别当已支持的能力宣传**。
- ★ **一个实测发现（工具自己会报）**：8bit 的六位十六进制**不带 alpha**（源码用 chroma 的 `.hex()` 也是这样），
  所以 **淡入/淡出 + 8bit ⇒ 24 帧颜色其实是同一组**（`distinctColorFrames` = 1，`notes[]` 里点破）。
  要让透明度真的变化，只能开 `use4bit`（`#RGBA` 第 4 位是 alpha）。
- **jitter 用固定种子**（`seed`，默认 12345）：源码用 `Math.random()`，一个要"可复现"的工具不能这样。

#### 回执读法

`output:"lua"` ⇒ `lua` / `luaBytes` / `lines` / `target`（`mode`/`controlName`/`templateIndex`/`fps`）/ `handoverFrom`
/ `frameCount` / `distinctColorFrames` / `framesPerLine[]` / `nextStep` / `warnings[]` / `needsHandover[]` / `unverified[]` / `deviations[]` / `notes[]`。

`output:"data"` ⇒ `frameCount` / `colorFrameCount` / `sizeFrameCount` / `distinctColorFrames` / `frames[].lines`（逐帧正文）
/ `frames[].charCount` / `tags` / `unverified[]` / `deviations[]` / `notes[]`。

- `summaryOnly:true` ⇒ **只去正文**（lua 模式去掉 `lua`、留 `luaBytesOmitted`；data 模式去掉逐帧文字、留字数），
  **统计 / `nextStep` / `warnings` / `needsHandover` 一个都不删**（有测试钉住）。
- `frames:[0,3]`（仅 `output:"data"`）可以点名只要那几帧；不给就出前 **60** 帧（其余用 `framesOmitted` 报数）。

#### 移植的 5 处**刻意偏差**（回执 `deviations[]` 里原样带出）

1. 风格枚举自己命名；
2. 默认色标钉死（源码默认是**随机色**，不可复现）；
3. 色标采样改成**线性 sRGB 插值**（源码用 `chroma-js` 的 `chroma.scale()`；按拆解书建议**不引入该依赖**）——端点颜色一致，中间色可能略有差别；
4. 字号插值**修正**了源码的区间外取值（源码 `sT` 用了全局刻度 `t*sizeSegs`；2 个色标时两者逐值相同，≥3 个色标才可见差别）；
5. 跳字用固定种子 PRNG。

### `op=struct-json` —— 可直接导入千星的变量 JSON
输入一份**声明式字段表**，产出两种形态（都能直接粘贴/导入）：

```jsonc
// ① definition：结构体定义（与同仓库 25 份真实千星样例逐字段同形）
{ "type": "Struct", "struct_ype": "basic", "name": "[任务]章节",
  "value": [ { "key": "id", "param_type": "Int32", "value": { "param_type": "Int32", "value": "0" } } ] }

// ② value：结构体变量值（**位置参数、无 key**）—— 与样例里嵌套结构体的值、PixelArt 导出的变量同形
{ "structId": "1077936165", "type": "Struct", "value": [ { "param_type": "Int32", "value": "0" } ] }
```

- 给了 `variableName` 还会回 `variable` / `variableText`（「自定义变量」形态）。
- **24 个 ParamType**：`String StringList Int32 Int32List Float FloatList Bool BoolList Vector3 Vector3List
  Entity EntityList Guid GuidList ConfigReference ConfigReferenceList EntityReference EntityReferenceList
  Army ArmyList Struct StructList Dict NULL`（中文标签见 `lib/structvar/model.mjs` 的 `TYPE_LABELS`）。

#### 值编码（**从真实样例归纳**，不是猜的）

| 类型族 | 写法 | 样例出处 |
|---|---|---|
| `String` / `StringList` | 原样字符串 / 字符串数组 | `1077936165[任务]章节.json` |
| `Int32` `Guid` `ConfigReference` `EntityReference` `Army` `Entity`（及各自的 List） | 十进制**字符串**（列表 = 字符串数组） | 同上（`"0"` / `["0","1"]`） |
| `Float` / `FloatList` | **两位小数**字符串 | `"2.00"` / `"-1.00"` |
| `Bool` / `BoolList` | `"True"` / `"False"` | `PositionData.json` |
| `Vector3` / `Vector3List` | `"x,y,z"` | `PositionData.json` |
| `Struct` | `{structId, type:"Struct", value:[ParamNode…]}`（**位置参数**） | `PositionData.json` 的 `slot` |
| `StructList` | `{structId, value:[{param_type:"Struct", value:{…}}]}` | `PositionData.json` |
| `Dict` | `{type:"Dict", key_type, value_type, value:[{key,value}], value_structId?}` | `ActionGroup.json` / `二级区域字典.json` |

#### 两条**硬规则**（生成前校验，不通过直接报错）

1. **结构体 ID 必须 10 位数字**（`^\d+$` 且长度 == 10）—— 所有出现位置都查：`structId`、嵌套 `Struct`/`StructList` 的 `structId`、`Dict.value_structId`。
2. **单条文本 ≤ 500 字符** —— `String` 的值、`StringList` 的**每个元素**各算一条；超了**默认报错**并列出 `over[]`（路径 + 长度），
   要放行得显式 `allowLongText:true`（那时才降级成 `warnings[]`，与源码"网页允许保存但警告"的行为对齐）。

> ⚠️ 与源码的一处**刻意差异**：源码对 500 字符只 `toast.warning` 就放行 —— 我们默认拦。
> 理由是这条错误**要到千星导入时才暴露**，那时创作者已经白跑一轮。

#### `struct_ype` 这个拼写（兼容口径）

- **事实**：同仓库 **25 份真实千星结构体样例全部**写 `"struct_ype": "basic"`，整个仓库里搜不到 `struct_type`。
- 所以：**读入两个都认**（`struct_ype` 优先）；**默认写出 `struct_ype`**（跟着证据走）；要写 `struct_type` 传 `spelling`。
- 回执里 `spelling` / `spellingAlternative` / `spellingAccepted` 三个字段把「写了哪个、另一个叫什么、读认哪些」讲清楚。
- ⚠️ **未证实**：千星真正吃哪一个，我们手里**没有官方规格** ⇒ 回执 `unverified[]` 里点名这条。

#### 未验证项（别当"完整类型表"用）

`unverified[]` 会带：①24 个 ParamType **是否等于 7.1 的完整类型集**（对方 i18n 自述只覆盖「月之八」6.7 之前）；
②`struct_ype` / `struct_type` 哪个才是平台吃的拼写；③Float 两位小数与 Vector3 的数值格式（样例只见过这些形态）；
④500 字符上限是否仍是 7.1 的限制。

### 这一层**不做**什么

- **不写任何文件**（回执只是文本；`output:"lua"` 也只把 Lua 放在回执里，落盘走 `miliastra_code op=deploy`）；
- **不建控件、不建变量** —— 把 JSON 变成游戏里的变量、把「文本框控件名/模板索引/容器节点索引」告诉脚本，
  仍然是人在编辑器里做的事（本仓铁律：AI 不建控件/变量，但**可以给合法数据 + 可直接部署的 Lua**）；
- **不替创作者认控件类型**：`.gil` 里没有类型字段，候选只报名字（`imageTemplates` / `containerNodes` 也只是**名字启发式**），
  文本框 / 图片模板 / 容器一律由创作者确认；
- **不抓网图**：`pixel-art` 的图源只认**素材库 id** 或**本地绝对路径**，不连任何第三方 CDN；
- **不承诺 4bit 与真机渲染**：`use4bit` 默认关、开了也只在产物顶部加一行警示并进 `unverified[]`；
  离线端到端只证明"控件建出来了、颜色字段是这些值、块画在这几个位置"，**官方素材与真机渲染管线不覆盖**；
- 不吸收对方任何联网能力（登录 / OSS 直传 / Cloudflare Worker / 桌面伴侣 `127.0.0.1:27182`）。

## vfx：粒子特效（`miliastra_gen op=vfx-lua`，2026-09-30 · 第六批）

> 定位：**一次调用 → 可直接部署的粒子特效 Lua**（默认 `output:"lua"`），并把"效果"和"图"拆成两个正交维度。
> 驱动层（`Runtime` 采样/发射/池子/回收 + 晚建 + 诊断 + `error` 点名）**逐字取自真机定稿**：
> 工作区 `tmp/fx-demo/特效 fx.lua`（关卡 `1073741838` 第一屏星雨，**真机已跑通**）；
> 生成器只参数化三处：`VERSION` 行、预设名（日志标签）、`CONFIG` / `DATA` 两个数据块。
> 有断言钉住：`driverParity`（生成物里的驱动层必须与定稿件逐字一致）——
> 唯一允许的替换是把 `requireHandover("DURATION", …)` 换成 `requirePositiveNumber(…)`（**理由见下**）。

### 怎么用（AI 侧最短路径）

```json
{"op":"vfx-lua","preset":"list"}                       // 第 2 层：按需枚举（17 粒子（含 4 个组合）+ 3 图元 = 20 条，每条带二级分类 + 一句话 + 关键参数 + 控件核算）
{"op":"vfx-lua","preset":"peacock-in"}                 // 挑好就出 Lua（交接值缺了它会告诉你缺哪个）
{"op":"vfx-lua","preset":"coin-collect","imageId":101023,"previewImageId":100002}   // 真机用素材号、模拟器用圆预览
```
1. 先 `preset:"list"` 挑预设（**清单不进 schema** —— 那会每个会话都花几百字符）；
2. 再传 `preset` 拿 Lua + 核算（`pool` / `estimate` / `warnings` / `unverified`）；
3. 落地：`miliastra_code op=deploy`（**必须显式传 `level` + `file`**）→ 编辑器**存一次盘** → 真机试玩；
4. 想先在游戏外看一眼：`miliastra_sim op=bind`（`scripts[].sourceFrom` 给产物**绝对路径**）→ `op=frames` → `op=shot target=play`。

### 三个概念（换效果只动这三样）

| 概念 | 一句话 | 参数 |
|---|---|---|
| **预设** | 运动与节奏（**怎么动**） | `preset`（**17 粒子**（含 4 个组合）+ **3 图元** = 20 个；`preset:"list"` 列全，**每条带二级分类**） |
| **图片** | 身份与气质（**是什么**） | `imageId`（真机任意素材号）/ `previewImageId`（只为模拟器预览） |
| **路径** | 贝塞尔的"钢笔"三个手柄 | `path:{start?,p1,p2,target}` / `pathLayer` |

其余可调：`duration` / `loop` / `sizeScale` / `particlesPerEmitter` / `createAfterFrames` / `diagSteadyAt` / `parentName`。
**⚠️ `createAfterFrames` 别设 0**（层级铁律：不"晚建"会被全屏背景盖住，画面全空但控件都在）。

### 交接值（AI 拿不到、不许编）

| 值 | 从哪来 |
|---|---|
| `templateIndex`（图片控件模板索引） | `miliastra_map op=clientui` 读 `.gil`（**只有"无父节点"的独立模板能动态创建**）或创作者给；缺了 → `ok:false + needsHandover[]` |
| `container`（容器节点索引） | 同上；只作声明 + 自检（真机比 `prefabIndex`，不是 `id`） |
| `parentName`（一个屏幕上看得见的控件名） | 创作者给；**必须在"晚建之后"真实存在**（不然查不到，退回 `script.object`） |
| `imageId`（贴图号） | `miliastra_asset op=catalog` 挑；`chest-collect` **必须创作者给**（目录里没有名称字段，我们不猜）→ `needsImageId` |

### 两条"不许编"与一条"别误读"

- **不编索引**：缺 `templateIndex` 就 `ok:false`（编一个号 = 产物一跑就 `error`，白跑一局）。
- **不编素材号**：`chest-collect` 默认 `imageId:null`，不传就 `needsImageId`。
- ★ **别把"模拟器只画 6 个号"读成"平台只有 6 个号可用"**：真机可用 `op=catalog` 里**全部 1543 个素材号**
  （14 类，id 空间 `100001~112042`）；`simRenderable` 那列说的是**我们的模拟器**画不画得出。

### 回执字段

`lua` / `luaBytes` / `lines` / `preset` / `emitters` / `pool`（每层的 `need` vs `configured`）/ `estimate`
（落程、贝塞尔折线长、出生区是否超框、`budgetRatio`）/ `path`（最终生效的四个点 + 画布绝对坐标）/
`image`（`id` 真机 / `previewImageId` 预览 / `emittedImageId` 生成物里写的）/ `warnings[]` /
`unverified[]` / `doc`（**恒带一行文档指针**）/ `nextStep`。`summaryOnly:true` 只去正文（`lua` 或 `emitters` 全文），
统计与 `nextStep` 一个不删。

### 这一层**不做**什么 / 未验证

- **不做拖拽钢笔的 GUI**：`path` 给的是三个点的**坐标（结果）**，不是交互；要调手感请在网页编辑器里拖，然后把数抄回来。
- **不保证真机**：模拟器是离线渲染（`op=bind` + `op=frames` 能证明"脚本跑了 / 控件建了 / 画面在动"，
  **证明不了**官方素材、混合模式、层级遮挡、手感、帧率）。
- **未验证项**（回执恒列）：真机渲染、素材号在真机上的形状、每层 512 / 总计 1024 的**帧率**、
  `loop:true` 的观感、宝箱图号。
- **一处刻意的驱动层替换**：定稿件的 `requireHandover` 只认**正整数**（它校验模板索引那类交接值），
  而 `DURATION` 是**秒**、可以是小数（上游 `coins` = 2.5）⇒ 生成器**只**把这一句换成 `requirePositiveNumber`，
  替换不到就**报错**（不硬塞产物）。这个 bug 是模拟器端到端第一次跑抓出来的。

## `op=errors`（`miliastra_log`，2026-09-30 · 真机实战）★ 先跑这个

> **为什么要有它**：真机上那条致命报错（`缺少交接值 CONFIG.CONTAINER_INDEX：…` + `stack traceback:` +

- **八条形态**（逐条 `kind`；主 `kind` 取优先级最高的那条，全命中放 `kinds[]`）：

  `特效 fx.lua:428`（**带 `.lua`**）与 `特效 fx:428: in function 'x'`（**真机形态，不带 `.lua`**，file 是脚本显示名）。

## `preflight`（`miliastra_gen op=vfx-lua`，2026-09-30 · 真机实战）

投递前的可判定自检清单：7 项，逐项 `{item, ok, why}` —— `ok:true` 判据满足 / `ok:false` 确定不合格（`why` 说清真机后果）/
`ok:null` **判不了，如实标 unknown，绝不猜**。

`templateIndex 有` · `container 有` · `parentName 能在本关 .gil 里查到`（能查就查；读不到 `.gil` ⇒ `ok:null`）·
`imageId 是合法正整数` · `imageId 能在模拟器预览（100001~100006）`（`false` 时说清**真机正常**）·
`每层池 ≥ rate×lifetime.max` · `合计控件 ≤ 1024`。

**配套两条硬约束**：

1. **缺 `container` 与缺 `templateIndex` 同等对待** ⇒ `ok:false` + `needsHandover[container]` +
   `warnings[]` 里一条 **`code:"FX_CONTAINER_MISSING"`** 的强警告（对象形态，可机读）。
   ⚠️ 走"**硬拦**"那一档（不是"仍生成 + 事后警告"）—— 因为漏 `container` 时
   `deploy` / `lint` / `miliastra_sim` **三环全绿**，只有真机 `OnStart` error、整屏没有粒子，那种"三绿一红"最难排查。
2. 产物顶部一段**运行时依赖清单**：`TEMPLATE_INDEX` / `CONTAINER_INDEX` / `PARENT_BY_NAME` / `IMAGE_ID`
   各自的**来源**，缺哪项就写「**缺 → 运行时必 error**」。
